# 观测日志模板

> 本模板定义观测日志的标准格式。所有 `.agent/eval/logs/` 下的日志文件必须遵循此格式。
> 日志由 `eval-observer` 规则触发，委派子代理生成。主对话零开销，不直接执行日志生成。

---

## 日志文件命名

格式：`YYYYMMDD_HHmm_{任务简述}.md`

- 日期时间使用任务结束时的本地时间
- 任务简述使用 2-5 个中文关键词，如"RWA白名单改造"、"订单链路分析"
- 问题修复后的日志追加 `_postfix` 后缀：`YYYYMMDD_HHmm_{问题简述}_postfix.md`

---

## 日志格式

```markdown
---
date: YYYY-MM-DD
trigger: {对话结束 | 用户反馈 | 存档附带 | 熔断附带 | 问题修复后}
session_rounds: {对话轮数}
task_type: {任务类型关键词}
---

# 观测日志：{任务简述}

## 行为画像

| 维度 | 内容 |
|------|------|
| 任务类型 | {分析/编码/修复/CR/知识管理/其他} |
| 涉及模块 | {模块列表，2-5 个关键词} |
| 触发的 Skill | {Skill 名称列表，无则写"无"} |
| 查阅的知识资产 | {.notes/ 文件列表，无则写"无"} |
| 对话轮数 | {N} |

## 摩擦点

> 以下章节仅在存在摩擦点时填写，无摩擦点时整个章节删除。

### 根因分析

{为什么会出现摩擦——是知识缺失？Skill 路由偏差？上下文不足？范式不熟？}

### 修复方式

{最终如何解决摩擦}

### 工作流缺陷

{如果根因指向 Rule/Skill/知识资产的缺陷，具体描述是哪个文件的什么缺陷；如无则写"无"}

### 改进建议

{针对工作流缺陷的具体改进方案；如无则写"无"}

### 摩擦点标签

{至少选一个}：
- #知识缺失：.notes/ 缺少相关知识资产
- #Skill未触发：应触发但未触发的 Skill
- #Skill误触发：不该触发但触发了的 Skill
- #范式偏离：没有遵循已有的编码范本
- #上下文不足：缺少必要的代码/业务上下文
- #意图误判：错误理解了用户的意图
- #规则缺失：缺少必要的编码约束或行为规则

## 回顾性自检（仅触发方式"对话结束"时填写）

| 维度 | 内容 |
|------|------|
| 应触发未触发的 Skill | {回顾本次对话，是否有匹配场景但未加载的 Skill？列出名称和场景，无则写"无"} |
| 未修正的错误假设 | {AI 是否做出过错误假设（如引用不存在的类/方法）且未被用户纠正？描述内容，无则写"无"} |

---

## 记忆晋升评估（仅触发方式"问题修复后"时填写）

| 三问 | 结果 |
|------|------|
| Q1 跨会话复用？ | {YES/NO + 理由} |
| Q2 现有规则已覆盖？ | {YES/NO + 已覆盖的规则文件} |
| Q3 归属判断 | {仅 Q1=YES 且 Q2=NO 时填写：工程陷阱→项目记忆 | 工具教训→全局记忆 | 用户偏好→全局记忆} |

| 分流决策 | 结果 |
|---------|------|
| Q4 违反会导致严重后果？ | {YES→建议升级为 Rule；NO→保持 Memory} |

**晋升结论**：{晋升为 Memory / 建议升级为 Rule / 不晋升}

**晋升动作**（如需晋升）：
- 创建记忆文件到 {`.agent/memories/` | `~/.agent/memories/`}
- 更新对应 `MEMORY.md` 索引
```

---

## 日志归档规则

- 日志文件超过 **30 天**后，由 `workflow-retrospective` 执行回顾时移入 `.agent/eval/logs/archived/` 子目录
- 归档文件保留原命名，仅移动位置
- `workflow-retrospective` 生成回顾报告时读取归档日志作为数据源

---

## 不重复记录规则

- 同一次对话中，如果"对话结束"和"存档附带"都被触发，只生成一条日志（以存档附带为准，合并行为画像信息）
- 仅 1-2 轮的简单问答不生成日志，避免噪音
