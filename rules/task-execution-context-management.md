# 长任务与大上下文管理

> 本文件包含长任务持久化和上下文压缩规则。当对话轮次较长或上下文负荷过大时加载。

## 长任务先建任务再执行

以下场景**必须先创建任务文件夹再执行**：

| 场景 | 判定标准 | 原因 |
|------|---------|------|
| **跨多模块分析/修改** | 涉及 ≥3 个模块或 ≥5 个文件 | 上下文容易超出单次对话容量 |
| **全链路梳理** | 需要追踪入口 → 出口全链路 | 中间结果多，需持久化防丢失 |
| **Skill/规则优化** | 涉及多个 Skill 或 Rule 文件的联动修改 | 需分阶段执行，避免一次改太多出错 |
| **大规模重构** | 涉及接口签名变更、数据结构变更等 | 影响面大，需持久化 Spec 和影响清单 |

**执行方式**：调用 `task-spawner`，将目标、已知上下文、任务项持久化为 `.agent/context/` 下的任务文件夹，然后在新对话中执行。

## 上下文自主压缩

当 AI 在执行任务过程中**感知到上下文负荷过大**时，应**自主执行上下文压缩**，无需等待用户指令。

**触发条件**（满足任一）：对话轮次 ≥6 轮且仍有未完成任务项 / 单轮工具调用产生 ≥3 个大文件（>200 行）的完整内容 / 累计读取了 ≥10 个文件。

**压缩动作**：① 提炼关键结论（文件路径 + 一句话结论，丢弃原始代码细节）② 更新任务文件 ③ 标记已完成项 ④ 声明压缩。

**压缩原则**：
- **保留**：关键事实、文件路径、类名方法名、决策结论、排除理由
- **丢弃**：已读取文件的完整代码内容（需要时可再次读取）、中间搜索结果的完整列表
- **绝不丢弃**：用户明确提供的约束和边界、尚未完成的任务项

## 对话轮次存档提醒

当单次对话轮次 **≥8 轮**时，AI 应主动建议存档进度后开启新对话继续。用户确认后按 `task-persistence.md` 格式在 `.agent/context/` 下创建任务文件夹（或单文件）。
