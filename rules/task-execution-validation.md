# Spec 实体验证与设计交叉验证

> 本文件仅包含 Spec 验证和设计审视的执行规则。在 Spec 验证阶段加载，不包含 Spec 模板和执行流程。

## 步骤 4：Spec 实体验证

Spec 生成后，调用 `spec-verifier` Skill 自动验证 Spec 中引用的类/方法/配置是否真实存在、签名是否一致、模式是否合规。

- **P0 阻断项**（存在性/签名不匹配）：AI 先自动修正 Spec 并重新验证，修正后再呈现给用户
- **仅有告警**：连同验证报告一起呈现给用户判断
- **跳过条件**：小型跨文件修改（≤3 个子任务且不涉及新集成点）可跳过 P1 维度验证

## 步骤 5：设计交叉验证与多视角审视

调用 `spec-verifier` Skill 执行完整验证（含交叉验证和设计审视）。

## 步骤 6：Checkpoint 规则

等用户确认 Spec（含验证报告和交叉验证报告）后再继续。

- **可逆修改**（加逻辑、重构、新增文件等）：用户确认后直接实施，不打断心流
- **不可逆修改**（删文件、改数据库 Schema、改对外接口签名）：Spec 中必须标注风险，用户**显式确认**后再实施

## 步骤 8：质量防线触发规则

- ≥3 文件变更或接口变更时，调用 `code-review-checklist` Skill 审查。需要干净上下文审查时，可委派 子代理（Reviewer）。
- 修改文件 ≥5 个时，改为生成子任务简报避免上下文爆炸
