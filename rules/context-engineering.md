# 上下文工程与预算感知

> 设计理念：Token 是最昂贵的资源。每次决策前先评估"这个操作值多少 Token？"。
> 借鉴 Harness 运行时模式 + Loop Engineer 的主动管理思想。

## 一、上下文分层模型

```
🔴 热层（常驻，~3000 tokens）: CLAUDE.md + alwaysApply rules
🟡 温层（按需加载）: Skills + references + rules-dev
🟢 冷层（不加载，按需检索）: .notes/ 完整文档 + 历史日志 + memories
```

- **热层精简**：新增 alwaysApply rule 前，评估是否可降级为按需加载
- **温层精准**：Skill 路由按实际场景匹配，避免无关 Skill 驻留
- **冷层高效**：按需读取目标文件片段，不整文件加载

## 二、委派决策树

每次遇到以下场景，优先委派子代理而非在主对话中处理：

| 场景 | 决策 | 原因 |
|------|------|------|
| 跨多个文件/目录搜索 | → Explore Agent | 只读搜索，读摘要不读全文 |
| 代码分析（>3 个文件） | → general-purpose Agent | 保护主上下文 |
| 简单信息查询 | → 直接工具调用 | 无需委派 |
| 设计/规划讨论 | → 主对话 | 需要深度思考 |
| 编码实现 | → 主对话 | 需要全量上下文 |
| 代码审查 | → Workflow | 并行独立审查 |

## 三、压缩信号识别

当出现以下信号时，主动建议 `/compact`：

1. 对话轮数明显持续（主观判断 ≥15 轮实质性交互）
2. 已完成的独立任务 ≥2 个（中间步骤细节可丢弃）
3. 用户说"继续"、"下一个"（暗示上一任务已完成）
4. PreCompact Hook 已注入保留指令（系统已提示压缩）

**建议格式**：
> 上下文已较长，建议 `/compact` 压缩后继续。关键决策和未解决问题会自动保留。

## 四、自检（每次重要操作前）

1. 这个操作能在子代理中完成吗？（是 → 委派）
2. 需要全量上下文吗？（否 → 子代理 / 直接工具调用）
3. 上一独立任务已结束？（是 → 建议压缩）

## 五、禁止行为

- 禁止在主对话中进行大范围文件搜索（>5 个文件）
- 禁止把子代理读到的文件内容全文复制到主对话
- 禁止在对话轮数 ≥20 时不主动建议压缩
