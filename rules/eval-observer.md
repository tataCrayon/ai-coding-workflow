# AI 交互观测规则 — 委派模板与约束

> **设计原则**：守护线程模式——主对话零开销，观测工作全部委派给子代理。
> 日志模板见 `.agent/eval/log-template.md`，日志存储于 `.agent/eval/logs/`。
> **触发条件**已拆至 `eval-observer-triggers.md`（alwaysApply: true，常驻加载），本文件仅在需要生成日志时加载。

## 子代理 委派模板

```
【任务类型】编辑任务

【必须做】
根据以下信息，生成一条观测日志到 .agent/eval/logs/YYYYMMDD_HHmm_{任务简述}.md

触发方式：{对话结束 | 用户反馈 | 存档附带 | 熔断附带 | 问题修复后}
对话轮数：{N}
任务类型：{简述}
涉及模块：{模块列表}
触发的 Skill：{Skill 列表，无则写"无"}
查阅的知识资产：{.notes/ 文件列表，无则写"无"}
摩擦点：{具体描述，如无则写"无"——无摩擦点时删除日志中的摩擦点章节}

--- 回顾性自检（仅触发方式 1 使用）---
应触发未触发的 Skill：{回顾本次对话，是否有匹配场景但未加载的 Skill？列出 Skill 名称和对应场景，无则写"无"}
对话中是否存在未修正的错误假设：{AI 是否做出过错误假设（如引用不存在的类/方法、误判业务逻辑）且未被用户纠正？描述假设内容，无则写"无"}

日志格式参考 .agent/eval/log-template.md

【禁止行为】
- 不要修改任何业务代码
- 不要修改 .notes/ 或 .agent/ 下的文件
- 仅创建 .agent/eval/logs/ 下的日志文件
```

### 触发方式 5 专用委派模板（问题修复后）

当触发方式为"问题修复后"时，使用以下增强模板：

```
【任务类型】编辑任务

【必须做】
根据以下信息，生成一条摩擦点观测日志到 .agent/eval/logs/YYYYMMDD_HHmm_{问题简述}_postfix.md

触发方式：问题修复后
对话轮数：{N}
问题现象：{用户反馈了什么问题，AI 之前产出了什么错误结果}
根因分析：{为什么 AI 会做错——是知识缺失？Skill 路由偏差？上下文不足？范式不熟？}
修复方式：{最终怎么修复的}
涉及模块：{模块列表}
工作流缺陷：{如果根因指向 Rule/Skill/知识资产的缺陷，具体描述是哪个文件的什么缺陷；如无则写"无"}
改进建议：{针对工作流缺陷的具体改进方案；如无则写"无"}

摩擦点标签建议（至少选一个）：
- #知识缺失：.notes/ 缺少相关知识资产
- #Skill未触发：应触发但未触发的 Skill
- #Skill误触发：不该触发但触发了的 Skill
- #范式偏离：没有遵循已有的编码范本
- #上下文不足：缺少必要的代码/业务上下文
- #意图误判：错误理解了用户的意图
- #规则缺失：缺少必要的编码约束或行为规则

日志格式参考 .agent/eval/log-template.md，摩擦点章节必须包含上述根因分析和改进建议

--- 记忆晋升评估（仅触发方式 5 使用）---
记忆晋升三问：
Q1 跨会话复用？{YES/NO + 理由}
Q2 现有规则已覆盖？{YES/NO + 已覆盖的规则文件}
Q3 归属判断（仅 Q1=YES 且 Q2=NO 时）：{工程陷阱→项目记忆 | 工具教训→全局记忆 | 用户偏好→全局记忆}

分流决策（仅晋升时额外评估）：
Q4 违反会导致严重后果？{YES→建议升级为 Rule，在日志改进建议中标注；NO→保持 Memory}

晋升结论：{晋升为 Memory / 建议升级为 Rule / 不晋升}
晋升动作（如需）：创建记忆文件到对应 memories/ 目录 + 更新 MEMORY.md 索引

【禁止行为】
- 不要修改任何业务代码
- 不要修改 .notes/ 下的文件
- 可以创建 .agent/eval/logs/ 下的日志文件
- 可以创建 .agent/memories/ 或 ~/.agent/memories/ 下的记忆文件（仅记忆晋升时）
- 可以追加更新 MEMORY.md 索引（仅记忆晋升时）
```

## 约束

- **主对话零开销**：绝不在主对话中执行日志分析、回顾对话等操作
- **静默执行**：触发方式 1（对话结束时）的 子代理 委派不需要向用户说明，直接在结束语后静默执行
- **改进追踪**：如果方式 5 的日志中"改进建议"指向具体的 Rule/Skill/知识资产修改，`workflow-retrospective` 生成报告时应检查改进是否已落地，未落地的改进建议应在报告中标注为"待执行"
- **不重复记录**：同一次对话中，如果触发方式 1 和触发方式 3 都被触发，只生成一条日志（以存档附带为准，合并行为画像信息）
- **不打断心流**：绝不主动询问"要不要记录"
- **简短问答豁免**：仅 1-2 轮的简单问答不生成日志，避免噪音
- **日志归档**：`workflow-retrospective` 执行回顾时，将超过 30 天的 eval 日志移入 `.agent/eval/logs/archived/` 子目录
