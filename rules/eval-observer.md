# AI 交互观测规则

> **设计原则**：守护线程模式——主对话零开销，观测工作全部委派给 Sub Agent。
> 日志模板见 `.aicoding/eval/log-template.md`，日志存储于 `.aicoding/eval/logs/`。

## 触发方式（共 5 种）

### 1. 对话结束时自动生成行为简报 ⭐ 常态化采集

当用户**明确表示当前任务完成**（"好了"、"可以了"、"谢谢"、"结束"等结束信号）或**即将离开对话**时：
- 在主对话的结束语之后，**静默委派** Sub Agent 生成一条行为简报
- prompt 中携带：任务类型、涉及模块、触发的 Skill、查阅的知识资产
- 如果本次对话中存在摩擦点（用户纠正、AI 走弯路、重复搜索等），一并记录
- 如果没有摩擦点，仍然生成日志（仅包含行为画像，摩擦点章节留空或删除）

**不触发的场景**：
- 对话只有 1-2 轮的简单问答（如"XX 是什么意思？"）
- 用户在对话中途切换话题（此时对话尚未结束）

### 2. 用户显式反馈

当用户说"记录一个问题"/"这个问题记一下"/"标记问题"时：
- 在主对话中用 1-2 句话确认收到
- 委派 Sub Agent 生成观测日志，prompt 中携带用户描述的问题原文

### 3. 存档时附带

当上下文存档（`task-spawner` 的 PAUSE 模式）执行时，在写入存档文件后：
- 委派一个 Sub Agent 生成观测日志
- prompt 中携带：任务类型、涉及模块、触发的 Skill、本次对话中用户的纠正/不满表达（如有）
- 如果触发方式 1 已在本次对话中生成过日志，则存档时**不重复生成**

### 4. 熔断时附带

当 `circuit-breaker` 熔断协议触发时：
- 委派一个 Sub Agent 生成观测日志
- prompt 中携带：熔断类型、尝试次数、最终状态

### 5. 问题修复后自动分析根因 + 记忆晋升 ⭐ Compound Learning 闭环

当用户发出纠正信号（"有问题"、"不对"、"改错了"、"这样不行"、"你理解错了"等），且 AI 完成修复后：
- AI 先在主对话中用 2-3 句话简要说明根因（为什么之前做错了）
- 修复确认完成后，**委派 Sub Agent** 生成一条摩擦点日志
- prompt 中必须携带：问题现象、根因分析、修复方式、涉及的 Rule/Skill/知识资产缺陷（如有）
- 如果根因指向工作流自身的缺陷（如 Rule 缺失、Skill 路由偏差、知识资产过时），在日志中标注改进建议
- **记忆晋升评估**（Sub Agent 在生成日志后额外执行）：
  - Q1 跨会话复用？——下次做类似事情会再犯吗？NO→仅保留日志；YES→继续
  - Q2 现有规则已覆盖？——`anti-patterns.md`/`coding-standards.md` 已有此条？YES→标注"规则遵守失败"不晋升；NO→继续
  - Q3 归属判断：工程陷阱（模块位置/类用法）→项目记忆(`.ai/memories/`)；工具教训（搜索技巧/编辑技巧）→全局记忆(`~/.ai/memories/`)；用户偏好（PR 风格/代码风格）→全局记忆
  - 晋升动作：创建记忆文件（frontmatter 含 name/description/type/createdAt）+ 更新对应 MEMORY.md 索引

**判定标准**：
- 用户纠正 AI 的产出或理解 → 触发
- 用户讨论业务 bug 而非 AI 犯错 → 不触发
- 正常的需求追加或变更 → 不触发

**灰色地带（谨慎判断）**：
- 用户暗示有更优方案（"可以，但..."、"能不能换个方式"）→ 不作为纠正信号，但在对话结束时的行为简报中记录为"次优决策"
- 用户反复追问同一问题（可能意味着 AI 回答不到位）→ 第 3 次追问时视为纠正信号，触发根因分析

## Sub Agent 委派模板

```
【任务类型】编辑任务

【必须做】
根据以下信息，生成一条观测日志到 .aicoding/eval/logs/YYYYMMDD_HHmm_{任务简述}.md

触发方式：{对话结束 | 用户反馈 | 存档附带 | 熔断附带 | 问题修复后}
对话轮数：{N}
任务类型：{简述}
涉及模块：{模块列表}
触发的 Skill：{Skill 列表，无则写"无"}
查阅的知识资产：{.notes/ 文件列表，无则写"无"}
摩擦点：{具体描述，如无则写"无"——无摩擦点时删除日志中的摩擦点章节}

--- 回顾性自检（仅触发方式 1 使用）---
应触发未触发的 Skill：{回顾本次对话，是否有匹配场景但未加载的 Skill？列出 Skill 名称和对应场景，无则写"无"}
对话中是否存在未修正的错误假设：{AI 是否做出过错误假设（如引用不存在的类/方法、误判业务逻辑）且未被用户纠正？描述假设内容，无则写"无"}

日志格式参考 .aicoding/eval/log-template.md

【禁止行为】
- 不要修改任何业务代码
- 不要修改 .notes/ 或 .ai/ 下的文件
- 仅创建 .aicoding/eval/logs/ 下的日志文件
```

### 触发方式 5 专用委派模板（问题修复后）

当触发方式为"问题修复后"时，使用以下增强模板：

```
【任务类型】编辑任务

【必须做】
根据以下信息，生成一条摩擦点观测日志到 .aicoding/eval/logs/YYYYMMDD_HHmm_{问题简述}_postfix.md

触发方式：问题修复后
对话轮数：{N}
问题现象：{用户反馈了什么问题，AI 之前产出了什么错误结果}
根因分析：{为什么 AI 会做错——是知识缺失？Skill 路由偏差？上下文不足？范式不熟？}
修复方式：{最终怎么修复的}
涉及模块：{模块列表}
工作流缺陷：{如果根因指向 Rule/Skill/知识资产的缺陷，具体描述是哪个文件的什么缺陷；如无则写"无"}
改进建议：{针对工作流缺陷的具体改进方案；如无则写"无"}

摩擦点标签建议（至少选一个）：
- #知识缺失：.notes/ 缺少相关知识资产
- #Skill未触发：应触发但未触发的 Skill
- #Skill误触发：不该触发但触发了的 Skill
- #范式偏离：没有遵循已有的编码范本
- #上下文不足：缺少必要的代码/业务上下文
- #意图误判：错误理解了用户的意图
- #规则缺失：缺少必要的编码约束或行为规则

日志格式参考 .aicoding/eval/log-template.md，摩擦点章节必须包含上述根因分析和改进建议

--- 记忆晋升评估（仅触发方式 5 使用）---
记忆晋升三问：
Q1 跨会话复用？{YES/NO + 理由}
Q2 现有规则已覆盖？{YES/NO + 已覆盖的规则文件}
Q3 归属判断（仅 Q1=YES 且 Q2=NO 时）：{工程陷阱→项目记忆 | 工具教训→全局记忆 | 用户偏好→全局记忆}

分流决策（仅晋升时额外评估）：
Q4 违反会导致严重后果？{YES→建议升级为 Rule，在日志改进建议中标注；NO→保持 Memory}

晋升结论：{晋升为 Memory / 建议升级为 Rule / 不晋升}
晋升动作（如需）：创建记忆文件到对应 memories/ 目录 + 更新 MEMORY.md 索引

【禁止行为】
- 不要修改任何业务代码
- 不要修改 .notes/ 下的文件
- 可以创建 .aicoding/eval/logs/ 下的日志文件
- 可以创建 .ai/memories/ 或 ~/.ai/memories/ 下的记忆文件（仅记忆晋升时）
- 可以追加更新 MEMORY.md 索引（仅记忆晋升时）
```

## 约束

- **主对话零开销**：绝不在主对话中执行日志分析、回顾对话等操作
- **静默执行**：触发方式 1（对话结束时）的 Sub Agent 委派不需要向用户说明，直接在结束语后静默执行
- **改进追踪**：如果方式 5 的日志中"改进建议"指向具体的 Rule/Skill/知识资产修改，`workflow-retrospective` 生成报告时应检查改进是否已落地，未落地的改进建议应在报告中标注为"待执行"
- **不重复记录**：同一次对话中，如果触发方式 1 和触发方式 3 都被触发，只生成一条日志（以存档附带为准，合并行为画像信息）
- **不打断心流**：绝不主动询问"要不要记录"
- **简短问答豁免**：仅 1-2 轮的简单问答不生成日志，避免噪音
- **日志归档**：`workflow-retrospective` 执行回顾时，将超过 30 天的 eval 日志移入 `.aicoding/eval/logs/archived/` 子目录
