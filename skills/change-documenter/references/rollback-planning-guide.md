# 回滚计划指南（通用版）

> 供 `change-documenter` Skill 引用的回滚方案编制方法。

## 回滚方式选择决策树

```
变更是否含 DB Schema/数据迁移？
├── 是 → 需数据回滚脚本 + 代码回滚（双向）
└── 否 → 变更是否有功能开关？
         ├── 是 → 关开关即回滚（秒级，首选）
         └── 否 → git revert / 重新部署上一版本
```

## 回滚方式对照

| 方式 | 适用 | 生效速度 | 注意 |
|------|------|---------|------|
| 功能开关 | 有开关的新功能 | 秒级 | 首选，无需重启 |
| git revert | 纯代码变更 | 需重新部署 | 保留历史 |
| 版本回退 | 紧急故障 | 需重新部署 | 注意配置兼容 |
| 数据回滚脚本 | 有 DDL/数据变更 | 慢 | 必须预先准备+验证 |

## 数据回滚策略
- DDL 变更前备份表结构
- 数据变更前评估是否可逆
- 加字段（有默认值）通常无需回滚数据
- 改语义/删字段必须有回滚脚本 + 预发验证

## 多步骤回滚编排
若变更含多步（代码+DB+配置），回滚按**逆序**执行：
1. 关功能开关（阻断流量）
2. 回滚代码
3. 执行数据回滚脚本（如有 DDL）
4. 恢复配置
5. 验证核心功能 + 通知相关方

## 回滚触发条件（建议明确）
- 错误率 > 阈值持续 N 分钟
- 关键接口 p95 延迟 > 阈值
- 数据一致性告警
