# 接口安全约定（可选扩展）

> 接口安全与鉴权详细约定，供 `api-doc-generator` Skill 引用。金融/高安全场景使用；通用命名见 `api-naming-conventions.md`。

## 鉴权头格式规范
- 统一鉴权头（如 `Authorization: Bearer <token>` 或自定义签名头）
- OpenAPI 接口鉴权头集中定义为 `security scheme`，各接口引用
- 内部/外部接口区分鉴权方式（内部 Session/网关，外部签名）

## 签名参数说明（签名鉴权场景）
- 签名头通常含：appId、timestamp、nonce、signature
- 签名算法（如 SM3/HMAC-SHA256）在文档说明拼接规则和字段顺序
- 签名有效期（如 5 分钟）明确标注
- timestamp 防重放，nonce 防重复提交

## 幂等策略标记
- 写接口（POST/PUT）标注幂等机制：幂等键 header 或业务唯一键
- 幂等键存储与过期策略（如 Redis SETNX + TTL）在文档说明
- 重复请求返回首次结果，不重复执行副作用

## PII 脱敏规则
- 响应中敏感字段（手机号/身份证/银行卡）默认脱敏
- 脱敏格式统一（如手机号 `138****8000`）
- 明文返回需授权 + 审计日志
- 文档中敏感字段标注脱敏规则和授权条件

## 安全检查清单（接口设计时）
- [ ] 输入参数校验（防注入）
- [ ] 鉴权头定义完整
- [ ] 敏感字段脱敏规则明确
- [ ] 写接口有幂等机制
- [ ] 限流/防重放标注
- [ ] 操作审计日志
- [ ] 资源归属校验（防 IDOR）——外部传入的资源 ID 必须校验与当前用户/租户的归属关系
- [ ] 凭证不得硬编码——代码/配置文件中禁止明文凭证（密码/密钥/token），必须使用环境变量/配置中心/KMS

## 🔒 身份信息获取铁律

> Controller 层获取操作人/身份信息时，必须从框架鉴权后注入的上下文对象获取，禁止从 HttpServletRequest 直接读取 Header。

**铁律：身份字段必须从鉴权上下文（如 UserContext/TenantContext 类对象）获取，禁止 `request.getHeader()`/`getParameter()` 直接读取**

- 直接读 Header 的 `X-User-Id` 之类 → 身份可伪造（除非端点在受保护网关路由下且有强制覆盖策略）
- 直接读 `getParameter("userId")` → 更危险，可被任何人注入
- 正确做法：从鉴权拦截器注入的上下文对象取（操作人 ID / 用户名 / 租户 ID 各按项目框架的 ContextHolder 命名）

## 🔒 IDOR 归属校验约定

> 水平越权（IDOR）是金融场景最高频的安全风险之一——前端传入的资源 ID 若无归属校验，可被用于探测他人数据。

**铁律：从外部传入的归属 ID 必须校验与当前用户/租户的关系**

校验方式：
- Service 层校验：`资源ID → 查询确认该资源属于当前用户/租户`
- 框架拦截器保证：如果拦截器已确保所有查询自动追加租户/用户过滤条件，则无需手动校验
- 校验失败 → 返回 403 或 404（禁止返回他人数据）
- 典型需校验的字段：accountId、orderId、bindId、walletId——凡是"属于某用户"的资源 ID
