# Workflow Retrospective（工作流回顾与自省引擎）

> **核心定位**：闭合评估环。观测器负责"记"，本 Skill 负责"用"——从散落的观测日志中提取趋势、发现模式、输出可落地的改进建议。
>
> **设计哲学**：对标行业度量驱动理念 + Agile Retrospective 的回顾方法论，但适配 AI Coding 单人工作流的场景。

## 🎯 核心能力

| 模式 | 适用场景 | 输出 |
|------|---------|------|
| **A: 趋势报告** | 定期回顾（周/月/按需） | 量化报告 + 趋势图表（文本） |
| **B: 专题分析** | 针对某类反复出现的摩擦点深挖 | 根因分析 + 系统性改进方案 |
| **C: 改进建议** | 根据趋势数据建议规则/Skill 优化 | 具体的修改建议清单 |

## 🚦 触发时机

- 用户主动指令："生成观测报告"、"汇总最近的问题"、"工作流回顾"
- AI 建议触发：当观测日志目录中日志 ≥5 条且最近一次报告距今 ≥7 天时，可主动建议
- 与观测器联动：观测器负责采集，本 Skill 负责消费

## 🛠️ 执行流程

### Step 1: 数据采集（Gathering）

1. 使用 `列举文件` 扫描观测日志目录
2. 使用 `读取文件` 逐个读取所有日志文件（若 ≥10 个，使用 子代理 并行读取）
3. 使用 `列举文件` 扫描报告目录，确认上次报告时间
4. 可选：扫描任务上下文目录中的任务文件，提取熔断记录和推理链中的教训

### Step 2: 多维度聚合（Aggregation）

从所有日志中提取结构化数据，按以下维度聚合：

#### 2.1 标签频次统计

统计各摩擦点类型的出现频次，识别 Top 3 高频问题：

| 标签 | 出现次数 | 占比 | 趋势 |
|------|:-------:|:----:|------|
| #知识缺失 | N | x% | ↑↓→ |
| #Skill未触发 | N | x% | ↑↓→ |
| ... | ... | ... | ... |

#### 2.2 模块热力图

统计哪些代码模块/业务域最频繁出现摩擦：

| 模块 | 摩擦次数 | 主要问题类型 |
|------|:-------:|-------------|
| core-module | N | ... |
| ... | ... | ... |

#### 2.3 Skill 触发分析

统计 Skill 的触发/未触发情况：

| Skill | 触发次数 | 应触发未触发 | 误触发 |
|-------|:-------:|:----------:|:-----:|
| unit-test-master | N | M | K |
| ... | ... | ... | ... |

#### 2.4 时间趋势

按周/日维度观察摩擦点数量的变化趋势，判断工作流是在改善还是退化。

#### 2.5 冗余度分析（可选）

检查规则/Skill 之间的职责重叠：

| 文件 A | 文件 B | 重叠内容 | 建议 |
|--------|--------|---------|------|
| {rule1} | {rule2} | {重叠描述} | 合并/分离/保持 |

#### 2.6 元数据审计（可选）

| 检查项 | 通过 | 异常 |
|--------|:----:|------|
| 所有 Skill 有 version 字段 | ✅/❌ | {异常列表} |
| 所有 Skill 被主配置引用 | ✅/❌ | {异常列表} |
| description 长度 ≤200 字 | ✅/❌ | {异常列表} |
| 无废弃/无效的规则文件 | ✅/❌ | {异常列表} |

### Step 3: 洞察提炼（Insight Extraction）

基于聚合数据，回答以下关键问题：

1. **最痛的点是什么？** — Top 3 高频摩擦点及其根因模式
2. **哪些 Skill/Rule 需要优化？** — 基于触发分析识别路由偏差
3. **哪些知识资产需要补充？** — 基于 `#知识缺失` 标签识别资产空白
4. **工作流在改善还是退化？** — 基于时间趋势判断

### Step 4: 输出报告（Reporting）

使用 `create_file` 生成报告到报告目录。

**文件名规范**：`{日期}_retrospective_{周期}.md`
- 示例：`20260423_retrospective_weekly.md`

### Step 5: 输出交接（Handoff）

报告生成后：

1. **写入回顾时间戳**：更新 `.agent/eval/last-retrospective.md`，将 `lastRetrospective` 字段设为当前日期
2. **向用户输出**：

> 📊 **工作流回顾报告已生成！**
> 📄 路径：报告目录/{文件名}
>
> **关键发现**：{一句话概括最重要的洞察}
>
> **建议优先处理**：{最高优先级的改进建议}
>
> 💡 需要我立即执行某项改进建议吗？

## ⚠️ 约束

- **只读分析**：本 Skill 只生成报告和建议，不自动修改规则/Skill 文件
- **数据驱动**：所有洞察必须有日志数据支撑，禁止凭印象下结论
- **改进建议必须具体**：禁止"优化 XX Skill"这种模糊建议，必须说明改什么、怎么改
- **日志不足时降级**：若日志 < 3 条，告知用户数据不足以生成有意义的趋势报告，建议先积累更多观测数据

## 🔗 与其他 Skill 的协作

| 上游 | 本 Skill | 下游 |
|------|---------|------|
| `eval-observer` → 产出观测日志 | **聚合分析** | → `pattern-extractor` 提取可复用模式 |
| `task-spawner`（PAUSE 模式） → 存档中的教训 | **趋势判断** | → 本 Skill 的冗余度分析验证改进效果 |
| `circuit-breaker` → 熔断记录 | **根因分析** | → `skill-creator` 优化/创建 Skill |

## 质量自检

生成报告后，AI 必须检查：
- 每个洞察是否有对应的数据支撑？（禁止无数据的主观判断）
- 改进建议是否具体到可执行？（指明改哪个文件、改什么内容）
- 是否与上期报告做了对比？（如有上期报告）
- 报告篇幅是否合理？（不超过 200 行，聚焦关键信息）
