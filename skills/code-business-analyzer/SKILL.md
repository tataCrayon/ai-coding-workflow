# Code Business Analyzer (深度业务分析引擎)

> 五种深度分析模式，聚焦"理解业务逻辑"。
> 概念定位/术语追踪请使用 `code-concept-tracer`，资产生成请使用 `knowledge-asset-manager`。

> ⚠️ **上下文保护约束**：本 Skill 的 reference 文档仅在执行到对应步骤时按需读取，**严禁一次性全部加载**。每次最多读取 1-2 个最相关的 reference 文件。

## 模式总览

| 模式 | 名称 | 适用场景 | 粒度 |
|------|------|---------|------|
| **A** | 全链路业务解读 | "帮我分析订单流程"/"全链路分析" | 🔬 逐环节 |
| **B** | 聚焦业务规则解读 | "分析校验规则"/"这个环节的业务逻辑" | 🔍 单环节 |
| **C** | 场景对比分析 | "模块A和模块B有什么区别" | ⚖️ 对比 |
| **F** | 扩展点导航 | "这个接口有哪些实现" | 📊 矩阵 |
| **G** | 代码复杂度分析 | "最复杂的流程是哪个"/"技术债务" | 📈 度量 |

## 模式A: 全链路业务解读（三阶段）

适用于"帮我分析订单流程"/"全链路分析"/"这个流程做了什么"类需求。产出完整的业务规则手册。

### 三阶段执行策略

**阶段1：骨架扫描**（主 Agent 执行）
- 定位流程入口，提取流程骨架（所有处理节点、分支点、异步等待点）
- 对每个节点，定位对应的处理类/函数，读取核心逻辑摘要
- 输出：流程环节清单（环节名 → 处理类/函数 → 一句话描述）
- 参考 [代码地图生成指南（深度参考暂未沉淀，需要时让 AI 就地展开） 进行项目结构识别

**常见追踪路径**（参考，非固定步骤）：

```
入口(Controller/Handler/API) → Service/UseCase → Repository/DAO → 外部调用(RPC/HTTP/MQ)
```

实际路径按代码结构自主判断。

**阶段2：逐环节深入**（子代理 并行）
- 按业务环节分组，每组 2-3 个环节，分配给 子代理（最多 3 个并发）
- 每个 子代理 深入到具体实现层，提取业务规则卡片
- 参考 [业务语义提取规则（深度参考暂未沉淀，需要时让 AI 就地展开） 进行代码→业务语言映射

**子代理 委派质量标准**：每个 子代理 的 prompt 必须包含：
1. **任务类型**：只读调研任务
2. **分析范围**：明确的环节名称、处理类路径（从阶段1获得）
3. **分析深度**：追踪到具体实现层，提取业务规则卡片
4. **返回格式**：每个环节输出「业务规则卡片」（条件→满足→不满足+错误码）
5. **禁止行为**：不要修改任何文件，不要跨越分配的环节范围分析其他环节

**阶段3：整合输出**（主 Agent 执行）
- 汇总所有 子代理 的分析结果
- 生成完整的业务规则手册，包含流程图、规则卡片、错误处理速查表

### 与其他模式/Skill 的联动

> 💡 某个环节特别复杂？说"分析 {环节名} 的业务规则"切换到模式B深入
> 💡 发现多场景差异较大？说"对比 {场景A} 和 {场景B} 的差异"切换到模式C
> 💡 不确定要分析哪个流程？先用 `code-concept-tracer` 定位相关代码

## 模式B: 聚焦业务规则解读

适用于"分析校验规则"/"这个环节做了什么"/"开通条件是什么"类需求。只深入分析**一个特定环节**。

### 分析方法

**理解目标**：追踪到业务规则的最终实现层，提取"条件→满足→不满足"三元组（含错误码）。

**常见追踪路径**（参考，非固定步骤）：

```
入口(Controller/Handler) → Service/UseCase → Repository/DAO → 外部调用(RPC/HTTP)
```

实际路径按代码结构自主判断。

**关键动作**：
- 定位入口（从路由配置或入口类）
- 逐层追踪至最终实现
- 提取规则卡片 + 对比不同模块/环境/配置的处理差异

输出格式使用**业务规则卡片**（见下方"输出格式规范"）。

### 与其他模式的联动

> 💡 分析完规则后发现多场景差异？说"对比 {场景A} 和 {场景B} 的差异"（模式C）
> 💡 想了解规则所在流程的完整链路？说"帮我全链路分析 {流程名}"（模式A）

详细分析方法参见 [业务规则分析指南（深度参考暂未沉淀，需要时让 AI 就地展开）

## 模式C: 场景对比分析

适用于"模块A和模块B有什么区别"/"不同环境的流程差异"/"不同配置有什么不同"类需求。

### 对比维度

| 对比类型 | 典型问题 | 对比方法 |
|---------|---------|---------|
| **模块对比** | 模块A vs 模块B | 对比配置文件 + 接口实现差异 |
| **环境对比** | 开发 vs 生产 | 对比环境配置 + 特有逻辑分支 |
| **配置对比** | 配置A vs 配置B | 对比配置项差异 + 条件分支 |
| **版本对比** | v1 vs v2 | 对比代码差异 + 行为变化 |

输出格式使用**场景对比表**（见下方"输出格式规范"）。

### 与其他模式的联动

> 💡 对比发现某条规则差异较大？说"分析 {规则名} 的业务规则"切换到模式B深入
> 💡 想了解对比场景的完整流程？说"帮我全链路分析 {流程名}"（模式A）

## 模式F: 扩展点导航

适用于"这个接口有哪些实现"/"各模块的策略有什么不同"类需求。快速生成**接口/扩展点×模块**的实现矩阵。

### 分析方法

**理解目标**：生成"接口方法×模块"的实现矩阵，明确哪些模块覆写了哪些方法、实现差异是什么。

**关键动作**：
1. **定位接口/扩展点体系**：`搜索代码` 搜索接口定义，按业务域分组
2. **读取基类/默认实现方法列表**：读取默认实现类，提取所有 public/protected 方法
3. **扫描覆写/实现情况**：根据用户关注的方法范围，在各模块的实现中搜索方法名
4. **提取实现差异**：读取覆写代码，提取返回值差异、条件分支、是否调用默认实现

### 输出格式

| 方法名 | 业务含义 | 默认实现 | 模块A | 模块B | 差异说明 |
|--------|---------|---------|-------|-------|---------|
| getValidationRules | 校验规则 | 基础配置 | ✅ 覆写 | 继承 | 模块A按类型动态添加 |

详细分析方法参见 [扩展点导航指南（深度参考暂未沉淀，需要时让 AI 就地展开）

### 与其他模式的联动

> 💡 想了解某个扩展点方法的具体业务规则？说"分析 {方法名} 的业务规则"（模式B）
> 💡 想对比两个模块的扩展点实现差异？说"对比 {模块A} 和 {模块B} 的差异"（模式C）

## 模式G: 代码复杂度分析

适用于"系统中最复杂的流程是哪个"/"哪些代码需要重构"/"技术债务评估"类需求。

### 复杂度指标

| 维度 | 指标 | 数据来源 |
|------|------|---------|
| **流程复杂度** | 处理节点数×3 + 分支节点数×5 + 异步等待数×2 | 流程定义/配置文件 |
| **接口复杂度** | 方法数、覆写率、文件行数 | 接口/实现类 |
| **代码复杂度** | 超大文件(>500行)、外部调用数、try-catch块数 | 源文件 |

### 输出格式

- **流程复杂度排行榜**：流程名、各指标、复杂度分、风险等级（🔴极高/🟡高/🟢中/⚪低）
- **接口复杂度排行榜**：接口类、方法数、文件行数、覆写率
- **超大文件清单**：>500行的文件列表
- **重构建议**：按优先级排列的具体重构方案

详细指标体系和分析方法参见 [代码复杂度分析指南（深度参考暂未沉淀，需要时让 AI 就地展开）

## 子代理 编排指南

全链路分析（模式A）需要并行扫描，使用 子代理 提高效率。

### 编排原则

1. **按业务环节拆分**：每个 子代理 负责 1-3 个相关环节
2. **最多 3 个并行**：避免过多并行导致上下文碎片化
3. **携带上下文**：每个 子代理 必须携带阶段1的骨架信息
4. **明确边界**：告诉 子代理 只做调研不做编辑

各模式的 子代理 Prompt 模板参见对应的 reference 文件。

## 质量检查

### 通用检查项

- [ ] 每个结论是否有 📍 代码引用？
- [ ] 推测内容是否标注了 ⚠️？
- [ ] 常量/枚举值的业务含义是否来自代码注释（而非自行翻译英文名）？
- [ ] 是否列出了分析盲区？

### 模式差异化检查项

| 模式 | 重点检查 |
|------|---------|
| **A 全链路** | 环节是否全覆盖？环节间数据传递是否标注？错误处理速查表是否生成？ |
| **B 聚焦规则** | 每条规则是否有"不满足会怎样"？配置值是否溯源到具体 key 和默认值？ |
| **C 场景对比** | 对比维度是否完整（配置+实现+流程+条件分支）？差异原因是否从业务角度解释？ |
| **F 扩展点导航** | 实现矩阵是否覆盖所有模块？覆写 vs 继承是否区分？ |
| **G 复杂度分析** | 复杂度指标是否量化？重构建议是否按优先级排列？ |
