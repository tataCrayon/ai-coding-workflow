# 资产 Markdown 格式规范

> **设计原则**：所有资产的首要服务对象是 **AI Coder**（而非人类阅读者）。格式必须优化为：
> 1. **高检索命中率**：标题、标签、关键词必须覆盖 AI 在搜索时可能使用的搜索词
> 2. **零歧义可执行**：代码路径必须是可直接使用的全路径引用，而非模糊描述
> 3. **快速定位**：AI 拿到资产后能在 3 步内找到对应代码并开始工作

所有经过本技能生成或优化的资产，应遵循以下结构：

```markdown
# [资产标题]

> **更新时间**：YYYY-MM-DD
> **last_verified**：YYYY-MM-DD（Analysis 层必填字段。记录最近一次人工或 AI 验证资产与代码一致性的日期。超过 30 天未更新将被巡检标记为 stale，AI 加载时须声明过期风险）
> **业务域**：{domain}
> **核心实体**：[术语库中定义的标准名称]
> **关联标签**：[关键词1], [关键词2], [同义词/别名]
> **AI 检索关键词**：[列出 AI 搜索时可能使用的所有变体词，含业务术语、代码类名/方法名、枚举/配置名、中英文、缩写、口语化表达]
> **质量状态**：代码已验证 / 部分待验证；图谱已连接 / 待补链；索引已更新 / 待更新

## 1. 业务背景 / 核心意图
(一句话说清楚：这段逻辑解决什么业务问题，为什么存在)

## 2. 核心逻辑 / 规则解析
(使用项目符号或表格，提取清晰的条件→结果→异常)
(对于业务规则，必须包含：判断条件、满足时处理、不满足时的错误码和错误信息)

## 3. 关联代码入口 (AI 可直接使用)
(必须提供全路径类名/模块路径、方法名或可直接读取的配置路径；每条记录必须有验证方式，避免不可追溯)
| 角色 | 代码引用 | 关键方法/配置 | 验证方式 | 说明 |
|------|---------|--------------|----------|------|
| 业务入口 | `com.example.app.XxxServiceFacade` | `submit()` | `Grep` + `Read` 已验证 | 接口层入口 |
| 核心逻辑 | `com.example.app.XxxDomainService` | `process()` | `搜索代码` 已验证方法存在 | 领域服务 |
| 配置文件 | `app-module/src/main/resources/xxx-config.json` | `{bizCode}` | `Read` 已验证 | 相关配置 |

## 4. 知识图谱关联 (Graph Links)
(必须使用相对路径链接到其他相关资产，形成网状结构；链接必须真实存在，不能只保留示例占位)
- **上游前置概念**：[XX概念](../../foundation/glossary.md) — 关系：提供术语/配置前置理解
- **下游派生/影响**：[XX流程](../domain/flow.md) — 关系：受当前规则影响
- **横向对比/相关**：[同类实现](./similar.md) — 关系：同类实现对比

## 5. 资产质量自检
| 维度 | 评分 | 证据 | 待补 |
|------|------|------|------|
| 代码可追溯性 | ⭐⭐⭐⭐⭐ | 关键类/方法/配置均已验证并记录验证方式 | 无 |
| 知识图谱完整性 | ⭐⭐⭐⭐⭐ | Graph Links 已连接上游/下游/横向资产且无死链 | 无 |
| AI 检索友好度 | ⭐⭐⭐⭐⭐ | 关键词覆盖业务术语、代码符号、配置/枚举名、同义词 | 无 |
| 格式规范性 | ⭐⭐⭐⭐⭐ | 必填章节完整，无空占位 | 无 |
```
