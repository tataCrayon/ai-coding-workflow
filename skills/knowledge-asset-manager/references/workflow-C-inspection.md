# Workflow C：模板化巡检 (Template-based Inspection)

> **触发词**："巡检资产"、"检查资产健康度"、"资产覆盖率"、"全面整理资产库"

巡检采用**"模板-实例"**架构：模板定义检查标准，每次巡检基于模板创建独立的实例文件记录本次发现。

**严禁在单轮对话中强行一次性读取所有文件**（防上下文爆炸），必须转入**任务持久化管理模式**。

## C.0 巡检范围确认

触发后**必须先询问用户**确认巡检范围：
- **按域巡检**："只检查某个域的资产" → 仅扫描对应子目录
- **按层巡检**："检查所有 foundation 层资产" → 仅扫描 `.notes/foundation/`
- **全量巡检**："全面检查所有资产" → 扫描整个 `.notes/` 目录
- **覆盖率专项**："检查资产覆盖率" → 仅执行覆盖率分析（C.3），不做健康度检查

## C.1 创建巡检实例

确认范围后，基于下方【巡检任务存档格式】在 `.agent/context/` 下创建本次巡检的实例文件：
- 文件名格式：`{YYYYMMDD}_资产巡检_{scope}.md`
- 初始化所有待检查的子目录为 `pending` 状态

## C.2 分批执行巡检检查项（Map-Reduce 模式）

逐个推进子目录的巡检，每个子目录执行以下**五维健康度检查**：

| 检查维度 | 检查内容 | 严重级别 |
|---------|---------|---------|
| **① 格式合规** | 是否符合【资产 Markdown 格式规范】（含 AI 检索关键词、关联代码入口表格、Graph Links） | ⚠️ Warning |
| **② 术语一致性** | 使用的产品名、业务概念是否与术语库一致 | ⚠️ Warning |
| **③ 图谱连通性** | Graph Links 是否存在死链？是否是孤岛节点？ | 🔴 Error |
| **④ 代码-资产一致性** | 资产中"关联代码入口"表格里的类/方法是否仍然存在？ | 🔴 Error |
| **⑤ 冗余与索引** | 是否存在重复文件？是否已登记在 `knowledge-index.md` 中？ | ⚠️ Warning |
| **⑥ 鲜度检查** | Analysis 层资产的 `last_verified` 字段是否存在（该字段为 Analysis 层必填）？距今是否超过 30 天？超过则标记为 `stale`。AI 加载 stale 资产时须声明"⚠️ 该资产最后验证于 XX，内容可能过期，以代码为准" | ⚠️ Warning |

### 执行架构

```
                        ┌─ 子代理 1: 检查 foundation/        → 局部报告 1
                        │
Orchestrator (主模型)  ──├─ 子代理 2: 检查 patterns/          → 局部报告 2
        │               │
        │               ├─ 子代理 3: 检查 analysis/{domain1}/ → 局部报告 3
        │               │
        │               └─ 子代理 4: 覆盖率扫描（全局）        → 覆盖率报告
        │
        └── Reduce: 汇总所有局部报告 → 全局巡检报告 + 待修复清单
```

**Orchestrator 职责**（主模型，轻量化）：
1. 使用 `列举文件` 获取 `.notes/` 子目录列表
2. 按子目录切分任务，使用 `task` 工具一次性派发最多 5 个子代理
3. 如果子目录 > 5 个，分批派发（第一批完成后再派发第二批）
4. 收集所有子代理返回的局部报告
5. 合并去重，生成全局巡检报告
6. 更新巡检实例文件
7. **Orchestrator 严禁自行读取资产文件做检查**

### 子代理健康度检查任务 Prompt 模板

```
【任务类型】只读调研任务

【任务目标】
对 `.notes/{target_dir}/` 目录下的所有资产文件执行五维健康度检查。

【必须做】
1. 使用 列举文件 列出 `.notes/{target_dir}/` 下的所有 .md 文件
2. 逐个使用 读取文件 读取每个资产文件的完整内容
3. 对每个文件执行以下五维检查：

   ① 格式合规（⚠️ Warning）：
   - 是否包含"AI 检索关键词"字段
   - 是否包含"关联代码入口"表格
   - 是否包含"知识图谱关联 (Graph Links)"章节

   ② 术语一致性（⚠️ Warning）：
   - 先读取 `.notes/foundation/glossary.md`（如果存在）
   - 检查资产中的术语是否与术语库一致

   ③ 图谱连通性（🔴 Error）：
   - 检查 Graph Links 中的相对路径链接，验证目标文件是否存在
   - 检查是否是孤岛节点（完全没有 Graph Links）

   ④ 代码-资产一致性（🔴 Error）：
   - 提取"关联代码入口"表格中的所有代码引用
   - 使用 文件搜索 验证对应的源文件是否存在

   ⑤ 冗余检查（⚠️ Warning）：
   - 检查同目录下是否有标题/内容高度相似的文件

4. 汇总所有发现，按以下格式返回结果

【禁止行为】
- 不要修改或创建任何文件
- 不要读取目标目录以外的资产文件（术语库和代码验证除外）

【返回格式】
---
## 巡检局部报告：{target_dir}
- 检查文件数：{N}
- Error 数：{N}
- Warning 数：{N}

### 🔴 Error
| # | 资产文件 | 检查维度 | 问题描述 | 建议修复方案 |
|---|---------|---------|---------|------------|

### ⚠️ Warning
| # | 资产文件 | 检查维度 | 问题描述 | 建议修复方案 |
|---|---------|---------|---------|------------|

### 文件清单
| 文件名 | 格式 | 术语 | 图谱 | 代码一致性 | 冗余 |
|--------|------|------|------|-----------|------|
---
```

### 子代理覆盖率扫描任务 Prompt 模板

```
【任务类型】只读调研任务

【任务目标】
扫描项目代码库中的核心组件，与 `.notes/` 资产进行交叉比对，计算资产覆盖率。

【必须做】
1. 扫描项目中的核心组件类型（{根据项目技术栈配置}）
   - 例如：Controller、Service、Repository、配置类、扩展点等
2. 使用 列举文件 递归扫描 `.notes/` 目录，获取所有资产文件列表
3. 对每个扫描到的代码组件，检查是否在任何资产文件中被提及
4. 按格式返回覆盖率报告

【禁止行为】
- 不要修改或创建任何文件
- 不要做深度代码分析，仅做存在性匹配

【返回格式】
---
## 覆盖率扫描报告

### {组件类型1} 覆盖率
- 已覆盖：{N}/{Total} ({percent}%)
- 缺失项：[{Name1}, {Name2}, ...]

### 综合覆盖率
- 总计：{N}/{Total} ({percent}%)
---
```

## C.3 Reduce：汇总全局巡检报告

Orchestrator 收集所有子代理返回的局部报告后：

1. **合并 Error/Warning 列表**
2. **合并覆盖率数据**
3. **跨目录去重**
4. **索引一致性校验**（Orchestrator 自行执行）
5. **生成全局巡检报告**：

```markdown
# 📋 资产巡检报告
- **巡检时间**：YYYY-MM-DD
- **巡检范围**：[全量 / 指定范围]
- **巡检结论**：[健康 ✅ / 需关注 ⚠️ / 需修复 🔴]
- **执行方式**：Map-Reduce（{N} 个子代理并行）

## 一、健康度检查结果

### 🔴 Error（必须修复）
| # | 资产文件 | 检查维度 | 问题描述 | 建议修复方案 |
|---|---------|---------|---------|------------|

### ⚠️ Warning（建议修复）
| # | 资产文件 | 检查维度 | 问题描述 | 建议修复方案 |
|---|---------|---------|---------|------------|

### 各目录健康度一览
| 子目录 | 文件数 | Error | Warning | 状态 |
|--------|--------|-------|---------|------|

## 二、资产覆盖率
（覆盖率子代理的返回结果）

## 三、待修复清单（需用户确认）
- [ ] 修复项 1：...
- [ ] 修复项 2：...
```

6. **更新巡检实例文件**

## C.4 修复策略决策

| 修复项数量 | 策略 | 执行方式 |
|-----------|------|---------|
| **≤ 5 项** | 当前对话直接修复 | 等待用户逐项确认后执行 |
| **> 5 项** | 渐进修复模式 | 持久化为 Checklist 任务，引导用户在新对话中逐项推进 |

## C.5 任务归档

全部完成后，将巡检实例文件中的状态更新为 `已完成`。

## 巡检任务存档格式

```markdown
# 资产巡检任务
- **创建时间**：YYYY-MM-DD
- **巡检范围**：[全量 / 指定范围]
- **状态**：进行中 | 已完成

## 子目录进度
| 子目录 | 状态 | 五维检查结果摘要 |
|--------|------|-----------------|
| foundation | ✅ completed | 格式✅ 术语⚠️(2处) 图谱✅ 代码一致性✅ 索引⚠️(1处) |
| patterns | 🔄 in_progress | - |
| analysis/{domain} | ⏳ pending | - |

## 覆盖率快照
| 维度 | 已覆盖 | 总数 | 覆盖率 | 缺失项 |
|------|--------|------|--------|--------|

## 发现汇总
### 🔴 Error
- [编号] [资产文件] [检查维度] [问题描述]

### ⚠️ Warning
- [编号] [资产文件] [检查维度] [问题描述]

## 断点信息
- **上次停驻点**：正在处理 `{dir}` 目录
- **已发现的全局问题**：[跨目录共性问题]

## 关键决策
- {决策} - 原因：{为什么}
```
