# Knowledge Asset Manager (知识资产管家)

本技能旨在建立一个健康的知识闭环，将零散的代码解读转化为结构化资产，构建**动态知识图谱**和**统一业务本体库**。它既能处理增量入库，也能对存量进行盘点与重构，还能通过模板化巡检保障一致性，更能在代码变动后自动校验并更新资产。

## 核心工作流总览

| 工作流 | 名称 | 触发词 | 何时使用 | 详情 |
|--------|------|--------|---------|------|
| A | 增量固化 | "保存资产"、"沉淀分析" | 保存新资产（最常见触发） | 下方详述 |
| B | 局部盘点 | "整理某模块资产"、"优化局部" | 整理少量已有资产 | 下方简述 |
| C | 模板化巡检 | "巡检资产"、"资产健康度"、"覆盖率" | 大规模健康度检查（Map-Reduce） | [workflow-C-inspection.md](references/workflow-C-inspection.md) |
| D | 恢复中断 | "继续整理资产"、"恢复巡检" | 继续上次中断的 C/E 任务 | 下方简述 |
| E | 校验与自动更新 | "校验资产"、"更新资产"、"代码变动后同步" | 发现问题 → 自动修复 → 汇报 | [workflow-E-validation.md](references/workflow-E-validation.md) |

## 工作流 A：增量固化 (保存新资产)

当用户要求"把刚才的分析沉淀下来"或"生成一份资产"时触发：

0. **内容来源判定**：评估对话上下文中是否已有足够分析内容。已有则直接进入步骤 1；不足则调用下方【可协作的分析型 Skills】获取内容，再进入步骤 1。本 Skill 不自行做深度代码分析。
1. **术语对齐与提取**：检查对话中是否出现了新的业务术语、产品名称。如果有，必须同步更新到全局术语库文件（如 `.notes/foundation/glossary.md`），并在当前资产中严格使用规范名称。
2. **内容结构化与图谱化**：按照 [资产格式规范](references/asset-format-spec.md) 组织内容，**必须**明确列出"上游依赖"和"下游影响"，将其编织进现有知识图谱，绝不产生孤岛节点。
2.5 **四维质量门禁**：落盘前必须自检并修正，未通过不得进入步骤 3：
   - **代码可追溯性**：`关联代码入口` 至少包含 1 个已验证代码入口，写明验证方式。
   - **知识图谱完整性**：`Graph Links` 至少提供 1 条真实可访问链接；确实无关联时写明"已检索，暂无可靠关联"并标记待补链。
   - **AI 检索友好度**：关键词覆盖业务术语、代码符号、配置/枚举名、中文口语化和英文/缩写变体；关键词应同步进入 `knowledge-index.md`。
   - **格式规范性**：元信息、业务背景、核心逻辑、关联代码入口、Graph Links、质量自检六类结构不得缺章或保留无意义占位符。
3. **归类落盘**：使用编辑工具保存到 `.notes/` 合适子目录。三层归类规则：
   - Foundation 层（`.notes/foundation/`）：项目级基础认知，极少变化
   - Patterns 层（`.notes/patterns/`）：可复制的编码范本、操作手册，跟随技术栈演进
   - Analysis 层（`.notes/analysis/{domain}/`）：特定业务链路深度分析，跟随需求生命周期
4. **强制更新索引**：**落盘后必须立即执行，不可跳过！** 读取 `knowledge-index.md`，将新资产的关键词、标题和相对路径作为新行插入对应层级表格区域。业务域表格不存在则新建。
5. **强制完成自检**：落盘和索引更新完成后，**必须输出以下检查清单**逐项确认。任何一项未通过必须立即补救；不能只写"已检查"，必须说明验证证据或补救动作：

```
✅ 资产落盘自检清单
- [ ] 文件已保存到 `.notes/{layer}/{domain}/` 正确目录下
- [ ] 代码可追溯性达标：至少 1 个入口已验证，写明验证方式
- [ ] 知识图谱完整性达标：至少 1 条真实链接已验证；暂无关联已显式标记
- [ ] AI 检索友好度达标：关键词覆盖术语、代码符号、配置名、口语和缩写变体
- [ ] 格式规范性达标：六类结构均存在且无空占位
- [ ] 已更新 `knowledge-index.md` 索引表
- [ ] Graph Links 指向的目标文件确实存在（无死链）
- [ ] 术语使用与全局术语库一致
```

**四维评分建议**：如用户要求评估资产质量，使用 1~5 星对四维度逐项评分，并给出扣分原因和修复建议。

## 可协作的分析型 Skills

当资产内容需要深度代码分析时，应主动调用以下 Skill 获取分析结果，然后由自己负责格式化、落盘和索引维护：

| 分析需求 | 调用的 Skill | 典型场景 |
|---------|-------------|---------|
| 业务流程/规则/代码解读 | `code-business-analyzer` | "帮我沉淀某个流程的业务规则" |
| 代码概念定位 | `code-concept-tracer` | "帮我沉淀某个概念涉及的所有代码位置" |

> **职责边界**：分析型 Skill 只负责产出分析内容（不负责落盘），`knowledge-asset-manager` 只负责格式化、落盘和索引维护（不负责深度分析）。

## 工作流 B：局部存量盘点与优化

当用户要求"整理某个模块的资产"、"盘点某几个笔记"时触发：

1. **局部扫描**：使用 `列举文件` 扫描 `.notes/` 下特定子目录，或读取全局索引表获取清单。
2. **深度阅读与确认**：批量阅读目标资产，评估健康度——术语校验、图谱连通性、代码溯源、冗余与索引。
3. **输出重构计划**：向用户输出《资产整理建议报告》。
4. **执行重构**：Skill 输出末尾附带确认请求，**主会话等待用户确认后**才执行资产重写、合并、改名或删除，并同步更新索引表。（Skill 工具单次调用无法暂停，确认由主会话负责）

## 工作流 D：恢复中断的资产整理任务

当用户在新会话中要求"继续整理资产"、"恢复巡检/校验"时触发：

1. **扫描存档**：扫描 `.agent/context/` 查找包含"资产巡检"/"资产校验"关键词且状态为"进行中"的任务文件。
2. **识别任务类型**：巡检 → 恢复到工作流 C，校验 → 恢复到工作流 E。
3. **读取并恢复**：提取已完成/未处理的子目录和断点信息。
4. **重建待办**：调用 `todo_write` 重建任务列表，从第一个 `pending` 任务继续。
5. **无缝衔接**：衔接到对应工作流的分批执行步骤。

## 防错与防腐约束

1. **禁止断链/孤岛**：新建或重命名文件时，**必须**同步更新索引表并在新文件中建立 Graph Links；无法找到可靠链接时必须显式标记"待补链"并说明已检索范围。
2. **术语一致性**：所有资产中的核心概念必须与全局术语表保持完全一致。
3. **禁止过度脑补**：原笔记缺失的代码逻辑且当前上下文中没有时，不要凭空捏造，应标记"待验证"并查证后再补全；严禁把推断写成已验证事实。
4. **引用必须可追溯**：类名、方法名、配置项、表名、枚举值必须尽量记录验证方式；未验证的引用必须标注"用户描述/待验证"。
5. **修改前防线**：大范围合并或删除文件前，必须输出计划并得到用户明确同意。
