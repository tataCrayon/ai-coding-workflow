# Doc Template（文档模板管理器）

> **核心定位**：全局文档模板管理中枢（不绑定特定项目）。既是一个**文档生成工具**（AI 读取代码库自动填充模板占位符），也是一个**模板管理工具**（添加、创建、修改模板）。

**模板文件位置**：本 Skill 的模板资产位于 `~/.claude/skills/doc-template/assets/` 目录下。

## 执行流程

### Step 0: 意图识别与模式选择

根据用户意图自动选择执行模式，**不需要向用户确认模式**：

| 用户表达 | 模式 | 说明 |
|---------|------|------|
| "写技术方案"、"生成文档"、"用模板写"、"技术设计文档" | **USE** | 使用现有模板生成文档 |
| "添加模板"、"新增模板" | **ADD** | 在现有模板基础上添加新章节/字段 |
| "创建模板"、"新建模板"、"从头设计模板" | **CREATE** | 创建全新的文档模板 |
| "修改模板"、"改模板"、"优化模板" | **MODIFY** | 修改现有模板结构/内容 |

**复合意图**：用户可能同时要求多个操作（如"用模板写文档，然后优化模板"），按顺序执行，每个模式完成后再切换。

### Step 1: USE 模式 — 使用模板生成文档

#### 1.1 加载模板

`Read` 加载模板文件 `~/.claude/skills/doc-template/assets/tech-design-doc-template.md` 全文。

> 如果有多个模板文件（未来扩展），优先使用用户指定的模板，无指定则使用默认模板 `tech-design-doc-template.md`。

#### 1.2 收集需求信息

从用户输入中提取以下关键信息（用户未提供的，AI 自行从代码库推导）：

| 信息项 | 来源 | AI 可推导？ |
|--------|------|------------|
| 关联 PRD 与参考材料 | 用户输入 + 需求分析文档(01-requirements.md) | 部分（AI可从01文件提取，无01文件需用户提供） |
| 需求概述 | 用户输入 + 需求文档 | 部分 |
| 涉及模块/文件 | 用户输入 + 代码扫描 | 是 |
| 接口/Controller | 代码扫描 | 是 |
| 实体类/字段变更 | 代码扫描 | 是 |
| 状态机枚举 | 代码扫描 | 是 |
| Nacos 配置 | 代码扫描 | 是 |
| MQ Topic | 代码扫描 | 是 |
| Redis Key | 代码扫描 | 是 |

#### 1.3 AI 自动填充

对模板中标注 `<!-- AI:auto:xxx -->` 的占位符，AI 主动执行代码扫描填充：

**扫描策略**（按优先级）：

1. **模块定位**：`Grep` 搜索用户指定的关键词/类名，定位涉及的 Controller/Service/DAO/Entity
2. **接口推导**：从 Controller 类提取 @RequestMapping/@PostMapping 等注解，生成接口列表
3. **实体推导**：从 Entity/DO 类提取字段和关系，生成 ER 图（Mermaid `erDiagram`）
4. **状态机推导**：从状态枚举类 + 状态转换逻辑提取状态定义和转换规则
5. **配置推导**：`Grep` 搜索 @Value/@ConfigurationProperties/RedisKey 定义/MQ 注解
6. **错误码推导**：搜索 ErrorCode 枚举/常量类
7. **上下游推导**：从 Feign Client/MQ Producer/Consumer 推导上下游依赖

> **⚠️ 重要原则**：AI 可推导的信息**不要反问用户**，直接扫描代码填充。只有用户必须提供的信息（如业务决策）才需要用户输入。**关联 PRD 与参考材料**应优先从需求分析文档(01-requirements.md)自动提取，无该文件时才请用户提供。

#### 1.4 生成文档

将填充后的模板内容写入目标文件：

- **默认输出路径**：`.aicoding/docs/{日期}_tech-design_{需求简述}.md`
- **用户指定路径**：按用户指定位置写入
- **仅展示**：用户说"先看看"/"预览"时只在对话中展示，不写文件

#### 1.5 人工补充提醒

生成文档后，在末尾列出**需要人工补充的项**：

```markdown
---
### ⚠️ 需人工补充/确认的项
1. 关联 PRD 与参考材料 — 如01-requirements.md不存在或关联材料不完整，需人工补充
2. 状态机图需确认 — AI 从代码推导，请验证是否符合业务意图
3. 灰度策略 — 需运维/产品决策
4. ...
---
```

### Step 2: ADD 模式 — 添加模板内容

在现有模板基础上添加新章节或字段：

1. `Read` 加载当前模板文件全文（路径：`~/.claude/skills/doc-template/assets/tech-design-doc-template.md`）
2. 与用户确认添加位置和内容（**章节级变更需确认，字段级直接执行**）
3. `Edit` 修改模板文件
4. 展示变更摘要

**变更规则**：
- 添加新章节：在对应位置插入，保持编号连续
- 添加新字段/表格行：在对应表格中插入行
- 添加新占位符：标注 `<!-- AI:auto:xxx -->` 或 `<!-- 手动填写:xxx -->`

### Step 3: CREATE 模式 — 创建新模板

创建全新的文档模板：

1. 与用户确认模板用途和章节结构
2. 参考现有模板的设计规范（占位符格式、AI 标注方式、表格结构）
3. 编写新模板文件，放入 `~/.claude/skills/doc-template/assets/` 目录
4. 更新本 skill.md 的模板列表（当前可用模板表格）

**新模板命名规范**：`{用途}-doc-template.md`，如 `api-doc-template.md`、`deploy-doc-template.md`

### Step 4: MODIFY 模式 — 修改现有模板

修改现有模板的结构或内容：

1. `Read` 加载目标模板全文
2. 与用户确认修改范围（**结构性变更需确认，文案微调直接执行**）
3. `Edit` 修改模板文件
4. 展示变更摘要和修改后的完整章节预览

> **修改原则**：最小差异原则——只改需要改的部分，不重写整个模板。修改后必须保持占位符格式一致。

## 模板资源管理

### 当前可用模板

| 模板文件 | 用途 | 章节数 |
|---------|------|--------|
| `assets/tech-design-doc-template.md` | 技术方案设计文档（默认） | 7章+附录 |

### 模板文件规范

所有模板文件必须遵循以下规范：

1. **文件头**：包含用途说明和 AI 友好设计说明
2. **占位符格式**：
   - `<!-- AI:auto:xxx -->` — AI 可从代码库自动推导填充
   - `<!-- AI:填写指引 -->` — AI 需要理解填写意图，但需要外部信息
   - `<!-- 手动填写:xxx -->` — 必须人工提供，AI 无法推导
3. **章节约定标注**：每个章节标注 `[必填]`/`[选填]`/`[有则必填]`
4. **表格为主**：信息以结构化表格呈现，便于 AI 填充和读者查阅
5. **Mermaid 图**：状态机/时序图/ER 图/流程图统一使用 Mermaid 语法（```mermaid 代码块），禁止使用 PlantUML/ASCII 艺术。Mermaid 在 GitLab/GitHub/Typora/VS Code 预览兼容性更好，且 AI 可直接生成

## 反模式

- ❌ 用户说"写技术方案"时，直接在对话中输出文本而不使用模板
- ❌ AI 可以从代码推导的信息，反复问用户确认（如"要不要我搜索Controller？"）
- ❌ 生成文档时不标注需要人工补充的项
- ❌ 修改模板时重写整个文件而非最小差异修改
