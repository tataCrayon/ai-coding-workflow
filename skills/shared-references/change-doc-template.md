# 变更留痕文档模板（通用版）

> 通用变更留痕文档模板，供 `change-documenter` Skill 引用。项目有特有规范时以项目为准。

## 核心原则
- 所有结论必须来自代码差异与提交信息，不得臆测
- 变更留痕文档是主产物，README 摘要为可选
- 信息不完整时用 `待补充` 占位，不中断输出

## 文档模板

```markdown
# 变更留痕 — {变更简述}

## 1. 背景
- 需求来源：{链接/编号}
- 变更目的：{一句话}
- 变更类型：新功能 / 缺陷修复 / 重构 / 配置

## 2. 影响范围
- 受影响模块：{去重列表}
- 关键文件：{3-10 个}
- 非模块目录变更：{数量}

## 3. 行为变化（Before/After）
| 变化类型 | Before | After |
|---------|--------|-------|
| 接口 | ... | ... |
| 数据 | ... | ... |
| 流程 | ... | ... |
| 配置 | ... | ... |

## 4. 风险与验证
- 风险点：{见 risk-assessment-guide}
- 验证命令：{至少1条，实际执行的}
- 验证结果：{通过/失败 + 关键现象}

## 5. 回滚方案
{见 rollback-planning-guide，至少一种可执行路径}
```

## 行为变化提炼规则
优先提炼：
- **接口变化**：入参、出参、状态码、异常
- **数据变化**：字段、校验、映射、默认值
- **流程变化**：分支、条件、顺序、幂等
- **配置变化**：开关、超时、重试、依赖

每个变化点写 Before/After。

## 金融场景扩展字段（可选）
资金相关变更额外记录：资金流向是否双向处理（正向+退款/冲销）、精度是否受影响、对账是否需调整、合规审计要求。
