# 数据库命名规范（通用版）

> 通用数据库命名规范，供 `database-design-guard` Skill 引用。项目有特有规范时以项目 `.notes/` 为准。

## 表命名
- 统一使用小写字母 + 下划线分隔（snake_case）
- 建议统一表前缀（如 `t_`）以区分业务表与系统表；带业务域前缀区分归属（如 `t_order_detail`、`t_product_info`）
- 禁止大写字母、驼峰命名、中文或特殊字符
- 表实体类不使用 `Dto`/`DO`/`Entity` 之外的混杂后缀

## 列命名
- 统一小写 + 下划线分隔（snake_case）
- 禁止列名中含大写字母（如 `trade_Direction` → `trade_direction`）
- 禁止整表列名全大写
- 与 ORM 实体字段映射注解保持一致

## 索引命名
- 唯一索引：`uk_{表名简称}_{列名}`
- 普通索引：`idx_{表名简称}_{列名}`
- 联合索引：`idx_{表名简称}_{列1}_{列2}`

## 约束命名
- 主键：`pk_{表名}` 或默认 `PRIMARY`
- 外键（如使用）：`fk_{子表}_{父表}`

## 注释
- 每个表和每个列都必须有注释（推荐业务语言）
- 类注释中的表名必须与 ORM 表名注解一致

## 命名不一致治理
历史表存在命名不统一时（如逻辑删除字段 `deleted`/`delete_flag`/`is_deleted` 混用），应：
1. 规范中明确唯一推荐命名
2. 历史表在数字资产文档中标注例外
3. 新表强制遵循，迁移时逐步收敛
