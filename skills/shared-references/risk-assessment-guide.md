# 风险评估指南（通用版）

> 供 `change-documenter` Skill 引用的风险评估方法。

## 风险等级判定决策树

```
变更是否影响资金/数据一致性/对外契约？
├── 是 → 高风险
└── 否 → 变更是否影响核心流程/多模块联动？
         ├── 是 → 中风险
         └── 否 → 变更是否可通过版本控制快速回退？
                  ├── 是 → 低风险
                  └── 否 → 中风险
```

| 等级 | 特征 | 要求 |
|------|------|------|
| 高 | 资金/数据一致性/对外契约/DB Schema | 必须有监控+回滚方案+灰度 |
| 中 | 核心流程/多模块/接口签名 | 需回归测试+回滚路径 |
| 低 | 单文件/日志/文案/新增可选功能 | 常规验证即可 |

## 影响面分析方法
1. 列出变更文件 → 归类模块
2. 追溯每个变更点的调用方（上游）和被调用方（下游）
3. 识别跨模块契约变化（接口签名、消息结构、DB字段）
4. 评估存量数据/存量调用方的兼容性

## 金融场景特殊风险项（可选）
- 金额精度/舍入变化 → 高风险
- 资金流向单向处理（漏了退款/冲销）→ 高风险
- 幂等失效导致重复扣款 → 高风险
- 状态机变更未追溯所有消费方 → 中高风险
- 敏感数据脱敏遗漏 → 合规风险
