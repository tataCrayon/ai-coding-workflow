# 金融领域数据库规范（可选扩展）

> 金融/资金场景的数据库详细规范，供 `database-design-guard` Skill 引用。非金融项目可忽略本文件。通用字段/命名见 `schema-field-conventions.md` 和 `db-naming-conventions.md`。

## 一、金额精度标准

| 场景 | 类型 | 说明 |
|------|------|------|
| 金额 | DECIMAL(20,4) | 精确到 4 位小数，禁止 FLOAT/DOUBLE |
| 费率/利率/汇率 | DECIMAL(10,6) | 精确到 6 位小数 |
| 份额/数量 | DECIMAL(20,8) | 高精度份额场景 |
| 币种 | CHAR(3) | ISO 4217 币种代码 |

**铁律**：金额计算全程 BigDecimal + 显式 RoundingMode，DB 层禁止浮点类型。

## 二、审计字段规范（资金表强化）

在标准公共字段基础上，资金相关表建议额外：
- `version`（乐观锁）**必带**——防止并发扣款/退款的更新丢失
- 关键金额变更需有流水表（不可变追加，only INSERT），禁止直接 UPDATE 覆盖历史
- 流水表含：业务单号、变更前余额、变更金额、变更后余额、操作类型、操作时间、操作人

## 三、索引设计指南

- 资金查询高频字段（账户号、订单号、状态、时间）建索引
- 对账类查询用联合索引覆盖（如 `idx_flow_account_time`）
- 避免在大文本/大金额备注字段建索引
- 注意索引失效：函数计算、隐式类型转换、前缀模糊查询

## 四、数据安全要求

- 敏感字段（银行卡号、身份证、手机号）存储加密或脱敏
- 查询返回默认脱敏，仅授权场景返回明文
- 审计日志记录敏感数据访问（userId + action + 时间戳）
- 逻辑删除而非物理删除，保留资金数据可追溯性

## 五、变更与兼容

- **允许**：新增表、新增字段（有默认值）
- **需评审**：修改金额字段类型/精度、删除字段、修改索引
- **禁止**：删除字段后改语义复用、不兼容的精度变更
- 金额精度变更必须评估存量数据影响 + 提供迁移方案
- 历史不合理设计走「标记废弃 → 访问收敛 → 迁移下线 → 文档化」流程
