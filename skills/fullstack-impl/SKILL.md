# FullStack Impl：逐任务执行，证据说话

## 前置检查（每次执行会话开始）

1. 读 STATUS.md + 当前 plan 文件的勾选状态（不是读对话历史）。
2. 读坑账本中与本任务同域的条目（构建/测试/adb 对应小节）。
3. 确认分支/工作区干净（git status），上批次的提交在。

## TDD 纪律（superpowers 规则，个人项目裁剪版）

- 引擎/数据/解析等**纯逻辑层**：严格红-绿。测试先行，没亲眼看到它红过就不算写了测试。
- **UI 层**：允许先写界面再补 widget 测试（视觉迭代快，先行成本大于收益），
  但行为逻辑（按钮启用条件、状态流转）仍要测试先行。
- 测试前已经写了的生产代码：删掉，从测试重来。
- 改测试预期来适配新行为是最后手段；真实用户反馈推翻旧预期时合法，
  但测试注释必须写明依据（哪个用户反馈/哪条需求编号）。

## 子代理分工（主对话是稀缺资源）

| 活 | 派给谁 | 主对话收什么 |
|----|--------|-------------|
| 全仓搜索/读码考古 | Explore 类子代理 | 一页纸结论 + file:line |
| 测试红了修到绿 | 修测子代理（模板见 know-u-time .agents/agents/test-fixer.md） | 结论行 + 每处修复的文件:行号+根因 |
| 实机走查/截图 | 验收子代理（同目录 emulator-verifier.md） | 验收报告：预期/实际/证据路径 |
| 设计评审 | fullstack-design（主对话跑，需要用户审美参与） | 问题清单 P0-P2 |

派发提示词三要素：**自包含**（不依赖对话历史，环境事实内联）/ **边界**
（只修不改需求语义；只验收不修码）/ **报告格式**（结论行 + 证据 + 基线变化）。
子代理模板做法：把「环境事实 + 已知坑 + 流程 + 边界」固化成 .agents/agents/*.md，
一次写好反复用——这是 know-u-time 提效最大的单点实践。

## 防自由发挥三则

1. 只做任务清单上的事。发现「顺手可以加」的东西 → 记入 plan 的「后续」节，不做。
2. 命名/文案拿不准 → 用需求文档原词（用户拍过板的词不许 AI 改写：
   「周末坐饭」就是「周末坐饭」，打错字也不改）。
3. 引入新依赖/新表/新权限 → 停下回 spec，这不是执行层的决定。

## 每任务完成动作

勾选 plan → 跑该任务验证命令贴证据 → 把一行结论压回 plan 文件。
全部任务完成 → 转入 fullstack-verify。
