# FullStack Verify：批次收尾七项

一项不过不提交。每项都要有**本轮新鲜证据**，不接受「应该没问题」「上轮跑过」。

## Checklist

1. **测试绿**：全量跑（分包/分模块跑，数字对齐 STATUS 基线记录并报新基线数）。
   证据 = 输出末尾计数行。从 package 目录跑（跨项目坑：从根跑可能触发不到构建钩子）。
2. **静态分析零告警**：analyze/lint 清零不留尾巴。证据 = 「No issues found!」。
3. **实机走查**：release 构建 + 实机（模拟器/真机）覆盖安装，用 a11y 树断言关键链路
   （入口可见 → 操作 → 状态落位），不靠肉眼截图。派验收子代理执行，
   主对话只读报告。涉及 schema 迁移时加验：旧数据还在、无崩溃。
4. **提交规范**：中文前缀风格（或项目既有风格），一批次一提交，
   格式 `<project>: <主题>（…N 测全绿）`。提交前 git status 无意外文件，
   .tmp/ 等临时产物已清。
5. **文档回写**：dev-log 追加阶段小节（做了什么/为什么/踩了什么坑）；
   STATUS 更新「当前阶段/下一步」；test-map/code-map 若有变动已同步（fullstack-trace）。
6. **坑账本**：本批次新踩的坑已按「现象→根因→对策」入账。
7. **跨会话交接**：durable 的决策与坑写入 agent 记忆（区分「本次相关」与
   「换台机器还得知道」）；plan 文件勾选状态最终确认。

## 完成声明格式（给用户看的收尾报告）

```
✅ <批次名> 完成：<一句话交付了什么>
- 测试：N 全绿（上基线 M → 新基线 N），analyze 零告警
- 实机：<验收结论行>，证据 <截图/报告路径>
- 提交：<commit hash> <message>
- 下一步：<STATUS 里的下一步，一句话>
```

## 红线复查（每批次提交前扫一眼）

- 密钥/凭据类文件不入库（.env / key / 签名文件，gitignore 生效确认）。
- 平台标识类字段不改（包名/bundle id 等备案锁定项）。
- 数据 schema 变更必有迁移路径 + 旧数据兼容验证。
- **AI 功能批次附加节**（本批次涉及 LLM/提示词/Agent 改动时）：金样本回归已跑且通过；
  提示词版本已 bump + 生成器已重跑（流程见 fullstack-trace）；key 未入库；
  AI 失效降级路径未破坏。完整门禁见 fullstack-ai。

## 验证资源坑速查（Flutter/Android 特化）

详见坑账本（工作区 `.agent/eval/logs/` 摩擦点记录（本包未内置 pitfall-ledger））测试/实机两节：
- 测试慢/爆内存：确认从 package 目录跑、必要时 -j 1、防残留 dart.exe 锁文件。
- 实机输入：CJK 不进 adb、tap 坐标以 dump bounds 为准、a11y 树优先于像素采样。
- 这些坑第二次踩还没对策 = 账本失职，先修账本再继续。
