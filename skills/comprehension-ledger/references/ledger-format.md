# Ledger 格式规范

`.agent/understanding/ledger.md` 是理解账本的唯一状态文件。本文件定义其格式与演化规则。

## 完整模板（首次 bootstrap 时生成）

```markdown
# 理解账本（Comprehension Ledger）

> 人可直读。每个需求一节；复习队列里的题按 Leitner 盒调度。
> 铁律：不评分不 KPI；毕业即止；账本有界。

## 复习队列

| 题 | 链路 | 盒 | 下次复习（第 N 个需求） | 状态 |
|----|------|----|----|------|
| （示例）为什么校验放 openapi 而不是 webportal？ | 产品下架链路 | 0 | 下个需求 | 待复习 |
| （示例）如果 hub 推 CONFIRMED 但无成交数据会怎样？ | 订单确认推送 | 2 | 第 5 个需求 | 待复习 |

## 理解资产（毕业题归档，不再考）

- （示例）为什么钱包绑定用异步 KYT？——同步会阻塞绑定期望 <30s（2026-09-11 毕业）

---

## <日期> | <需求名>

- 链路: <一句话说清改动落在哪条链路，点名上下游>
- 交接: 一页纸 ✓ / 时序图 <相对路径> / 自测 Q1✓ Q2✗ Q3✓
- 入队: <答错的题 → 盒 0>（没有则写「无」）
```

## 字段规则

### 复习队列

| 字段 | 规则 |
|------|------|
| 题 | 一句问句；问"为什么/会怎样"，禁止"是哪个文件"式背诵题 |
| 链路 | 业务链路名（人读的），不是表名/类名 |
| 盒 | 0/1/2；答对 +1（2 再对即毕业），答错归 0 |
| 下次复习 | 以**需求次数**计数：盒 0 = 下个需求，盒 1 = 隔 1 个需求，盒 2 = 隔 5 个需求 |
| 状态 | 待复习 / 毕业（毕业即移入「理解资产」节，从队列删除） |

### 需求节

- 一节 ≤15 行；超了说明一页纸没写好，回炉。
- 交接三件套允许缺件（M 级需求可只有一页纸），但缺件要如实标注，不装全。
- 自测结果用 ✓/✗ 记号即可，**禁止写"答得很差""再次答错"这类评价语**。

## 演化规则

1. **队列只减不增是健康态**：新题来自 H2 答错，毕业不断出队。队列长期 >8 题说明补课模式没触发够。
2. **同一题连错 2 轮** → 状态改「补课中」，AI 重讲链路后重新出题；讲不清链路的题作废（说明原方案没讲清，回填文档）。
3. **需求节不删**：即使需求下线，节保留（历史），只有队列题会毕业出队。
4. **账本文件放工作区/仓库根 `.agent/understanding/`**，加入 .gitignore 由个人持有（理解状态是个人资产，不进团队评审）——团队想共享时另出团队版文档，不要混用同一文件。
