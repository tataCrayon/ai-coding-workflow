# Comprehension Ledger（理解账本）

> **债的隐喻自洽**：每个需求记一笔理解资产（已通过的自测）或理解负债（答错的题）；负债有利息（复习队列），还清才销账。设计依据与调研见 OPT-036。

## 存储（唯一状态文件，人可直读）

```
.agent/understanding/ledger.md     ← 工作区级账本
```

格式：每需求一节（链路一句话 + 交接三件套状态 + 自测结果）+ 复习队列表（题/链路/盒/到期/状态）。

## 四个寄生钩子协议

### H1 边界问答 —— 宿主：backendflow-spec（签收门禁前）

1. 把方案中**非平凡决策**转成「如果…会怎样」边界题；**选题材于重要性而非凑数**——只出能检验"是否理解主流程/核心业务"的题，trivial 决策走默认决策（D）不进问答。数量不设硬上限，以"用户愿意逐条回答"为预算上限。
2. **问答题（Q）与默认决策（D）分开编号、分节呈现**；默认决策只需一句"如无异议按此生效"的确认，签收时须显式复述待生效的默认决策清单。
3. 用户口答；答不上的点**回填进 1 页主文档**（信息量由理解缺口驱动）。
4. 原话与答案要点记入 Sign-off 节。

### H2 理解交接 —— 宿主：backendflow-understand

三件套（一页纸/实码时序图带 file:line/3 道自测）执行细节见 backendflow-understand SKILL.md；本钩子负责**收尾写入账本**：需求节 + 答错题入队（盒 0）。

### H3 间隔复习 —— 宿主：backendflow-spec（开工第一步）

1. 读账本复习队列，取**到期题 ≤2 道**，用户口答。
2. 答对：盒 0→1→2（隔 1/2/5 个需求）；**连续 2 次答对毕业**，题转入「理解资产」清单。
3. 答错：回盒 0（下个需求就复习）。
4. **补课模式**：同一题连续 2 轮答错 → 判定「不是遗忘是没懂」→ AI 重新讲该链路（可引用 `.notes` 业务资产 + 图），讲完重新出题。
5. 队列空：输出一行「复习队列空」，不阻塞。

**调度单位是「需求次数」不是天数**——工程师的时间节拍是需求，且每开需求必经 spec。

### H4 能力盘点 —— 宿主：workflow-optimization-log（模式 A 留痕后）

Skill/Rule/工作流文件增删留痕时，输出一行提醒：「能力一页纸已过期（`.agent/understanding/capability-map.md`），建议刷新」。用户指令或月底例行刷新。

## 铁律

1. **账本是 human-facing 的**：markdown 直读，禁止迁去 jsonl/sqlite。
2. **不评分不 KPI**：只记通过/不通过 + 错题入队；禁止对用户输出负面评价——目标是理解不是考试。
3. **钩子只插一行**：宿主文件只见 `> 🎓 [ledger 钩子] …` 门禁行，宿主业务逻辑零改动。
4. **复习 ≤2 题/需求**：超过会变成考试地狱，用户将绕开整个体系。
5. **毕业即止**：毕业题不再考；账本有界（毕业出队），不无限膨胀。

## 路由透明化约定（全工作流生效）

加载非显而易见的 Skill 时输出一行：「用了 X，因为 Y」——用户始终知道哪个能力被用了、为什么。这是对「路由黑箱」的零成本解法。

## Token 预算

ledger 常驻元数据 ~120 tokens；每次 H1/H2/H3 执行注入 ≤2K；账本每需求 ~15 行、毕业出队有界。
