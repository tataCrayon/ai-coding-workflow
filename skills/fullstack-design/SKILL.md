# FullStack Design：两级 demo 门禁——先拍流程，再拍观感

前端需求往往说不清（用户不懂术语，AI 没有画面），**demo 就是澄清工具**：
文字聊十轮不如点一下。所以页面级工作一律两级门禁，每级一个可点击的 HTML demo，
用户签收后才写业务 UI 代码。

## 门禁总则

```
需求澄清(spec) → ① UX demo（灰阶低保真，拍「流程对不对」）
              → ② 视觉 mock（高保真，拍「好不好看」）→ plan → impl
```

- 两级都未签收 = 一行业务 UI 代码都不写。签收凭证（用户原话+日期）回填 spec 提案的 Sign-off。
- 纯逻辑变更（数据/引擎/解析）不进此门禁，直接走 spec→plan。
- 小改动（S/M 级改文案/改一个按钮位置）降级为：一张截图/一处 mock 局部确认即可，不摆全套仪式。

## 第①级：UX demo（低保真，灰阶线框）

产物四件：

1. **页面清单**：本需求涉及哪些页面/弹层，每个一句话职责。
2. **用户流**：从入口到完成的路径（含回流：取消/失败/返回去哪）。
3. **页面状态矩阵**：每个页面四态必须列全——**空 / 加载 / 错误 / 成功**，
   按需加分支态（无权限/离线/首次引导）。漏状态是走查期返工的头号来源。
4. **可点击 HTML demo**：单文件，手机框分屏并排 + 最简 JS 跳转（点按钮切屏），
   灰阶线框级（色块+占位文字，不追求好看，追求快），放 `docs/mockups/ux-<slug>.html`。

拍板问题只有三个：流程通不通？信息架构（什么放哪）对不对？漏了什么状态/分支？
用户手绘线框或编号列点时：AI 把它转成可点击 demo 回确认，不算跳过本级的产物。

## 第②级：视觉 mock（高保真）

在 UX demo 已拍板的同一批页面上做高保真：

- 先保证 `docs/design.md` 设计语言存在（没有就先立 Token，见下节）。
- HTML mock 沿用 demo 的页面与流程，套真实 Token（色板/字阶/圆角/图标），
  放 `docs/mockups/ui-v<N>-<slug>.html` + 截图 png。
- 图标专项走 ai-app-icon-prompting 全局 Skill（寓意先行/三范式/48px 可读性验收）。

## mock 预审（可选子代理，把 P0 滤在用户看到之前）

mock 交给用户前，可派一个预审子代理（自包含提示词：贴评审清单 + Token 表 +
mock 文件路径），对照清单逐条查，返回 P0-P2 问题清单。主对话修完 P0 再给用户看，
**用户只审一轮**。设计判断（风格取舍）留在主对话与用户之间，不外包。

## 设计语言文档（docs/design.md，一次立好反复引用）

```markdown
# 设计语言 v<N>
## 1. 设计观          一段话：参照系（如 Things 3/潮汐/flomo 的克制质感）+ 反面清单
## 2. Token           色板（主锚色 1 + 点睛色 1 + 中性纸色系 + 状态色只做小面积）
##                    字阶（展示层与正文层两种气质）/ 间距节奏（4/8/12/20/32，禁全场一个数）
##                    圆角/阴影（hairline + 多层，不均匀光滑）/ 动效参数（Motion Token）
## 3. 图标规范        一套体系内完成（线性/填充/像素不混搭），禁默认库图标直接上脸
## 4. 组件规范        卡片/按钮/输入条/空态……每组件一节：用哪个 Token 组合
## 5. 文案规范        术语表（全 App 统一叫法）/ 语气 / 禁 emoji 上脸（豁免需记录）
## 6. 页面状态矩阵    各页面四态的呈现约定（空态长什么样、错误怎么提示）
## 7. 评审记录        每轮评审结论追加（日期 + P0 问题 + 处置）
```

实现层把 Token 固化成单一来源文件（theme tokens/样式常量），
**任何页面不得出现 Token 之外的裸色值/裸字号**——防漂移的机械手段。

## 塑料感评审清单（每轮视觉评审必过）

- [ ] 一眼像框架 Demo 吗（默认导航/按钮/Chip 脸）？
- [ ] 颜色单色调平铺、无材质层次？
- [ ] 字重字号均匀无层级？有无展示层字体？
- [ ] 圆角/间距全场一个数字？
- [ ] 图标默认库通用脸？跨套混搭？
- [ ] 状态色大面积铺色（应退为点/缘标记）？
- [ ] 同一概念两个叫法？同一组件两种长相？

评审输出格式：问题清单按 P0-P2 + file:line（或页面名）+ 归因；每轮结论回写
design.md 评审记录。连续两轮同类 P0 = Token 没落地，修实现层单一来源。

## 与其他技能的关系

- UX demo 拍板前若有方案分叉 → 回 fullstack-spec 给选项签收；两级 demo 的产物都附进提案。
- 术语表变化 → 同步 fullstack-trace 的 code-map（文案常量落点）。
- 实机走查（verify 阶段）发现 UX 问题 → 回本技能补 demo 修订，不直接改码。
