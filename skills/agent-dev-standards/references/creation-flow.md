# 创建流程细则

SKILL.md 只保留阶段判断。本文件在创建、修改或审查 Agent 时读取。

## 判断当前阶段

不要因为用户说「做一个 Agent」就从零开始追问。先看对话和仓库里已经有什么：

| 已有证据 | 进入 |
|---|---|
| 只有想法或一句需求 | 捕获意图 |
| 目的清楚，但边界、owner 或停止条件缺失 | 追问缺口，一次一个 |
| 契约字段已回答 | 写契约初稿 |
| 契约已落盘 | 写最小评估，再生成宿主产物 |
| 已有 Agent，用户要求修改 | 先读旧契约；没有契约就先补，再改实现 |
| 用户要求审查 | 不重写，先按门禁指出缺什么 |

用户明确说「先别追问，直接写」时，记录这个决定，缺失字段保持草稿，不把草稿说成可上线。

## 捕获意图

从对话里先提取，不重复询问已经回答过的内容。只补这四项：

1. 这个 Agent 让使用者完成什么？
2. 什么请求看起来相关，但必须拒绝？
3. 成功时，别人能检查到什么交付物？
4. 它跑在哪里：现有平台、现有编码 Agent，还是必须新写运行时？

第四项默认是前两个。只有现有宿主确实无法表达其工具、权限或评估时，才进入新运行时。这个理由要写进契约。

## 一次一问

缺口多于一个时，按这个顺序问，每次只问一个：

1. owner 是谁？不能接受「团队」。
2. 哪个动作不可逆，或会影响生产、凭据、权限、外部接收方？
3. 失败、超时、越界时找谁？
4. 哪一条事实源是启动时必须读取的？
5. 什么结果算失败？

用户暂时答不出，就在契约里写成「未决」，状态保持草稿。不要替用户指定负责人或自治等级。

## 契约怎么写

使用 `assets/agent-charter.template.md`。写入前先确定目录：

- 用户指定了目录，就用指定目录。
- 仓库已有 Agent 目录，新契约放在该 Agent 旁，文件名是 `AGENT.md`。
- 两者都没有，先问一个目录，不把文件散落到当前工作区根目录。

写完后对照八项读一遍：目的、明确不做、具名 owner、动作及自治上限、允许的工具、成功标准、停止后找谁、下次复审日。缺一项就保留草稿状态。

自治上限只使用三个词：自主、批准后执行、只建议。低可逆且影响面不是低的动作，不得写成自主。

## 评估怎么写

草案阶段写 5 条，覆盖：主路径、边界、工具失败、越界拒绝、指令冲突。每条都要有输入和可观察结果。

「回答专业」「语气友好」不是可观察结果。「拒绝执行并指向 owner」或「输出的文件包含指定字段」才是。

准备上线时扩展到 10 条，并把运行证据链接写回契约。没有证据，上线门保持未通过。

## 宿主产物

契约签收前，不生成运行代码。签收后按宿主选择一种：

| 宿主 | 产物 | 不产生 |
|---|---|---|
| Dify、扣子、Langflow 等现有平台 | 一份平台配置清单：提示词文件、工具白名单、人工审批点、评估集位置 | 不新写平台 |
| 编码 Agent | `AGENT.md`、提示词文件、工具白名单、评估用例 | 不新增框架 |
| 必须新写运行时 | 先写不可用现有宿主的理由，再按工程参考分阶段实现 | 不在理由成立前写代码 |

需要对外时，只从契约投影一种接口：

- 给工具调用方用 MCP（[规范](https://modelcontextprotocol.io/specification)）。
- 给另一个 Agent 用 `assets/agent-card.template.json`（A2A Agent Card，[规范](https://a2a-protocol.org/latest/specification/)）。模板已对齐 A2A v1：AgentCard 必填 name、description、version、supportedInterfaces、capabilities、defaultInputModes、defaultOutputModes、skills；AgentSkill 必填 id、name、description、tags。owner、复审日和「明确不做」通过 `capabilities.extensions` 携带，不属于协议字段，接收方不识别扩展时照常可用。
- 给普通服务调用方用 OpenAPI（[规范](https://spec.openapis.org/)）。

投影与契约冲突时，以契约为准，不在投影里临时放宽权限。

## 审查输出

审查时使用这个结构，不改用户没有要求修改的文件：

```markdown
# Agent 审查：{name}

- 状态：草稿 / 可立项 / 可上线 / 未验证 / 下线候选
- 阻断项：
- 可上线前还缺：
- 不需要自研的部分：
```

阻断项只列会造成错误放行的问题：没有 owner、高影响动作被设为自主、没有停止条件、评估无法观察、对外投影宽于契约。

## 迭代

契约或提示词修改后，说明哪些评估用例必须重跑。只改措辞且不改变边界时，可以不扩评估集；改变工具、权限、输出或停止条件时，必须更新对应用例。

不要为了通过审查而降低自治风险的描述。风险不清楚时保持草稿。
