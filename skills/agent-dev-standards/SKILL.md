# Agent 开发标准（Agent 创建器）

把一个 Agent 想法推进到可签收、可复审的契约。规范不是一份写完即忘的文档，而是带状态后果的门禁：缺字段只能是草稿，复审过期就不再算生产 Agent。

## 创建 Agent 的流程

判断用户当前处于哪一步，只推进下一步：

1. 从对话和现有材料里捕获意图，不重复询问已经回答的问题。
2. 把缺口收成五件事：目的、明确不做、可检查的成功结果、宿主、owner。
3. 一次只问一个阻断问题；owner、不可逆动作和停止后找谁优先。
4. 用 `assets/agent-charter.template.md` 写契约初稿，缺项保持草稿。
5. 写 5 条可观察评估；准备上线前扩展到 10 条并附证据。
6. 只有契约可签收，才按宿主导出提示词、工具白名单或接口投影。
7. 根据真实运行结果修改契约，并说明哪些评估必须重跑。

用户说「不用追问，直接写」时可以写，但必须把缺失项标成未决，不能把草稿称为可上线。

详细判断规则读取 `references/creation-flow.md`。不要在本文件里临时发明另一套流程。

## 为什么先写契约

一个能生成提示词的流程，不会自动产生负责人、停止条件和复审日。先写运行代码，通常会把这些缺口藏进实现里，等使用后才发现没人敢改。

现有平台已经能运行 Agent。默认把契约交到现有宿主，不新写运行时、不重做追踪和评估平台。只有证明现有宿主无法表达工具、权限或评估时，才进入工程实现。

## 八项必填

缺一项，状态最高是草稿：

| # | 字段 | 不通过的样子 |
|---|---|---|
| 1 | 目的 | 同时承诺多个互不相关的结果 |
| 2 | 明确不做 | 只写「尽量安全」 |
| 3 | 具名 owner | 写团队、部门或平台组 |
| 4 | 动作及自治上限 | 低可逆且有实质影响，却允许自主执行 |
| 5 | 允许的工具 | 为将来可能使用而预接工具 |
| 6 | 成功标准 | 只能用「回答得好」评价 |
| 7 | 停止后找谁 | 失败后继续重试，没有升级人 |
| 8 | 下次复审日 | 没有日期，或过期后仍标为生产 |

自治上限只用三个词：自主、批准后执行、只建议。生产变更、凭据、权限和对外发送默认只建议。

## 三道门

| 状态 | 进入条件 | 不允许 |
|---|---|---|
| 草稿 | 任一必填项未决 | 生成生产配置或对外接口 |
| 可立项 | 八项齐全，评估草案至少 5 条 | 进入生产 |
| 可上线 | 至少 10 条评估、有证据链接、有回滚人 | 跳过复审 |
| 未验证 | 复审过期或证据失效 | 继续称为生产 Agent |
| 下线候选 | 连续一个复审周期无有效产出，或风险无法降级 | 静默保留在可用列表 |

## 对外投影

先有契约，再选择一种投影。不默认同时输出三种。

- 给工具调用方：MCP（[规范](https://modelcontextprotocol.io/specification)）。
- 给另一个 Agent：A2A Agent Card，从 `assets/agent-card.template.json` 起步（[规范](https://a2a-protocol.org/latest/specification/)，字段以官方 proto 为准）。owner、复审日和「明确不做」不是规范字段，模板放在 `capabilities.extensions` 里携带，不做扩展接收方可删。
- 给普通服务调用方：OpenAPI（[规范](https://spec.openapis.org/)）。

投影不得放宽契约中的工具、权限和自治上限。

## 工程标准何时读取

创建契约阶段不读取这些文件，避免把登记表误当成代码项目。只有进入实现、代码审查或发布门禁时，按需读取一种：

| 需要判断 | 读取 |
|---|---|
| 提示词版本、缓存和加载 | `references/prompt-management.md` |
| 注册、依赖和影响面 | `references/agent-registry.md` |
| 工具 schema 和失败恢复 | `references/tool-calling.md` |
| 评估维度和 CI 门禁 | `references/evaluation.md` |
| 注入、权限和数据隔离 | `references/safety.md` |
| 追踪和成本归因 | `references/agent-observability.md` |

生产代码还要用：

```bash
python scripts/validate_agent_standards.py <agent-project-dir>
```

脚本只检查约定目录中的工程痕迹。它通过，不等于八项契约通过；契约通过，也不替代脚本。

## 测试

创建或修改本 Skill 的流程后，用 `evals/evals.json` 的三个 prompt 做回归：生成请求不得直接放行，材料充分时必须落成契约，审查时不得把阻断项改判为通过。
