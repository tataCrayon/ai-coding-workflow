# Task Spawner (任务持久化中枢)

当需要**生成一个新任务**、**将子任务从当前对话分离**、或**存档当前对话进度**时，调用此技能。**本技能会自动生成状态文件到任务上下文目录**，而非仅输出到聊天窗口。

> ❌ **反模式**：收到"生成任务"或"保存进度"请求后，在对话中直接输出分析结论或任务描述文本。
> ✅ **正确做法**：无论是"生成任务"还是"保存进度"，最终产物必须是任务上下文目录下的状态文件。

**核心目标**：生成的状态文件必须包含**足够的信息让 AI 在新对话中独立完成任务或无缝接续**，做到不丢失信息、任务可用。

> **设计原则**：对话中的推理过程是"热状态"，状态文件不能只保存"冷结论"。必须把已走过的弯路、已确认的事实、已排除的方案都持久化，避免新对话从零开始重新分析。

## 执行流程

### Step 0: 意图校准与模式选择 (Mode Selection)

根据用户意图自动选择文件类型，**不需要向用户确认模式**：

| 用户表达 | 模式 | 文件前缀 | 说明 |
|---------|------|---------|------|
| "生成任务"、"创建任务"、"派生任务"、"拆出去做" | **TASK** | `{日期}_TASK_{任务简述}.md` | 子任务派生：生成独立可执行的任务 |
| "保存进度"、"存档任务"、"压缩上下文" | **PAUSE** | `{日期}_PAUSE_{任务简述}.md` | 进度存档：固化当前进度便于接续 |

**主动建议触发**（满足任一条件即主动建议 PAUSE 存档）：
- 对话轮次 ≥6 轮且仍有未完成的任务项
- 单轮工具调用产生的信息量 ≥3 个大文件（>200行）的完整内容
- 分析过程中累计读取了 ≥10 个文件
- 发现自己开始遗忘前期约束或重复搜索已查过的内容
- 对话轮次 ≥8 轮（无论是否有未完成任务）

建议话术："当前对话已较长（已 N 轮 / 已读取 N 个文件），建议存档进度后开启新对话继续。"用户确认后执行 PAUSE 模式。

**目标锚点三元组**（两种模式都必须提取并写入文件）：
1. 用户初始原话诉求
2. 最新明确目标
3. 当前停驻点/下一步

**非目标与边界**：如果用户说过"先别做/不要改/只分析/只记录"等约束，必须作为非目标或动作边界写入。

**歧义处理**：只有当"当前任务目标"和"下一步动作"无法从对话中确定时，才向用户澄清；不要为了可选细节打断用户。

### Step 1: 边界澄清 (Clarification)
分析当前的上下文。

**TASK 模式**：如果无法明确要分离的目标，主动向用户澄清：
- 该子任务的最终交付目标是什么？（例如：只是纯文本 Code Review 给出建议，还是要直接修改代码？）
- 有哪些文件是必须要纳入新会话视角的？

**PAUSE 模式**：调用 `todo_write` 确认最新的任务完成情况，回溯聊天记录收集全局状态。

### Step 2: 上下文提取与压缩 (Context Extraction)
基于当前的对话历史，**逐项提炼**以下内容，不要遗漏关键约束：
- **任务目标**：遵循任务命名规范（[动作] + [目标对象] + [具体内容]），必须具体到类名/方法名
- **业务背景**：Why are we doing this? 如果背景复杂，宁可多写几段也不要遗漏关键信息
- **推理链与关键上下文**（⚠️ 关键章节，不可省略）：
  - **信息来源与可信度**：区分 `已验证事实`、`来自用户描述`、`推断/待确认`；不要把推断写成事实
  - **已确认的事实**：对话中通过代码分析、搜索、阅读等方式确认的事实，附确认方式
  - **已排除的方案**：对话中讨论过但被排除的方案，附排除原因——避免新对话重走弯路
  - **关键决策**：对话中做出的重要决策，附决策依据
  - **工具活动摘要**：对话中执行的关键搜索/读取/分析动作及其发现
- **关联上下文文件**：新对话的 AI 必须阅读的文件路径，每个文件附一句话说明为什么要读
- **已落地的资产清单**（PAUSE 模式必填）：当前已经修改完毕、且无 Bug 的稳固成果
- **任务项清单**：具体的、可逐项执行的任务列表，每项遵循命名规范，已完成的打勾
- **边界与约束**：动作约束、质量约束、范围约束
- **验收标准**：明确的完成条件

### Step 3: 创建决策 + 生成状态文件 (Create State File)

#### 3.1 创建形式决策（硬约束）

根据任务持久化规范，**必须先判断输出形式**：

| 条件 | 输出形式 | 命名 |
|------|---------|------|
| 任务项 ≤3 且无需蓝图/参考材料 | **单文件** | `{MMDD}_{类型}_{任务简述}.md` |
| 任务项 >3 或需要蓝图/参考材料 | **文件夹** | `{MMDD}_{类型}_{任务简述}/` |

> ⚠️ 大多数正式需求开发任务都应走文件夹模式。单文件仅用于极简任务（如：只有1-2步的配置变更存档）。

#### 3.2 文件夹模式（推荐）

按任务持久化规范文件夹架构创建：

```
.agent/context/{MMDD}_{类型}_{任务简述}/
├── TASK.md        # 核心索引（<80行）：目标、状态、任务项、执行协议
├── CONTEXT.md     # 推理上下文：已验证事实、排除方案、决策
├── MAP.md         # 导航图（≥6任务项时生成）：速查表、依赖图、自检点
├── refs/          # 参考材料（按需）
└── deliverables/  # 交付物（按需）
```

- **TASK.md**：按任务持久化规范模板生成
- **CONTEXT.md**：按任务持久化规范模板生成
- **MAP.md**：任务项 ≥6 时生成，按任务持久化规范模板
- **BLUEPRINT.md**：编码阶段才生成（Spec 确认后），分析/设计阶段不创建

#### 3.3 单文件模式（仅限简单任务）

按任务持久化规范单文件模板生成单个 `.md` 文件。

#### 命名规范

`{任务简述}` 必须遵循任务命名规范，具体到类名/功能点。禁止写 `修改代码`、`处理逻辑` 等模糊描述。

### Step 4: 输出交接指引
文件生成后，根据模式输出不同的交接语：

**TASK 模式**：
> 子任务文件已生成！
> 路径：`.agent/context/{文件名}`
>
> 使用方式：在新对话中输入"执行 {任务简述}"即可开始。

**PAUSE 模式**：
> 🗜️ **上下文压缩完毕！**
> 进度和断点已安全封存于 `.agent/context/` 目录。
> 📄 路径：`.agent/context/{文件名}`
>
> 💡 **提效建议**：为了释放大模型的最佳智商，建议您现在**清理历史记录 / 开启全新的对话 (New Chat)**，并在新对话的第一句输入：
> `继续 xx 任务`（AI 会自动从 .agent/context/ 中查找对应的任务文件）

## 质量自检

生成状态文件后，AI 必须执行"可恢复性门禁"，未通过则先修正文件再回复用户：

### 通用自检项（TASK + PAUSE 都必须通过）
- **目标无漂移？** 文件中的任务目标是否能追溯到用户初始原话诉求和最新明确目标？
- **推理链完整？** 新对话的 AI 是否知道"前任已经确认了什么、排除了什么、做了什么"？
- **证据已分层？** 已验证事实、用户描述、推断/待确认是否分开记录？
- 关联上下文文件是否完整？（新对话的 AI 能否仅靠这些文件理解全貌）
- 任务项清单是否可逐项执行？完成状态是否准确？
- 边界约束是否明确？验收标准是否可判定？
- **新会话首步可执行？** 新对话只看状态文件时，第一步动作是否明确到可立即执行？

### PAUSE 模式额外自检
- **类型无混淆？** 用户只是要压缩对话时，是否生成 `PAUSE` 而非 `TASK`？
- 已落地的资产清单是否完整？（每个修改过的文件都列出来了吗）
- 当前断点是否精确？（新对话的 AI 是否知道从哪里接手、面临什么阻碍）

### 恢复性验收标准
状态文件必须满足：新对话中的 AI 在不读取旧聊天记录的情况下，能够回答以下 4 个问题：
1. 用户最初要解决什么，后来有没有变更目标？
2. 哪些事实已经验证，验证方式是什么？
3. 当前停在什么地方，为什么停在这里？
4. 接下来第一步应该做什么，哪些事情明确不能做？

## 与其他 Skill 的协作

> 协作是扩展能力，不影响本 Skill 的独立运行行为。

### 上游输入（谁的输出可以触发本 Skill）
- **`workflow-retrospective`**：生成改进建议后，复杂改进项可通过本 Skill 创建优化任务文件
- **`cr-review-pipeline`**：当 CR 修复项过多无法一次完成时，可通过本 Skill 持久化为任务文件
- **`java-change-impact-analyzer`**：影响范围过大时，可通过本 Skill 将影响清单转化为可执行的任务文件

### 下游输出（本 Skill 的输出可以流向谁）
- **任何 Skill**：生成的任务文件在新会话中恢复后，按任务内容路由到对应 Skill 执行
