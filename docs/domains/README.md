# 业务域文档（示例）

> verified: 2026-11-23 ｜ 验证方式: 模板占位，部署时替换

## 什么时候建 `domains/`

一个业务域值得建目录，当且仅当：

1. 它的规则**跨多个仓**生效（单仓的放那个仓）
2. 它会**反复被问到**（一次性调研放 `.specs/`）
3. 有**稳定的结构**可写（表、状态机、接口契约、权限模型）

## 目录约定

```
docs/domains/<domain>/
├── README.md          # 域概览：是什么、涉及哪些仓、入口在哪
├── <aspect>.md        # 按侧面拆：数据模型 / 状态机 / 权限 / 集成
```

一份 `README.md` 至少答三问：

| 问题 | 内容 |
|---|---|
| 这个域是什么 | 一句话 + 边界（不负责什么） |
| 涉及哪些仓 | 链接到 `repos/INDEX.md` 的对应行 |
| 从哪进代码 | 关键服务、关键表、关键接口 |

## 示例域：permission-system

部署本包时，把这个目录**替换成你自己的第一个业务域**，或直接删除（`docs/INDEX.md` 同步删行）。

示例内容见 [`permission-system/README.md`](permission-system/README.md)——它演示了「源头库 + 同步链 + 租户库」这种多仓机制的写法。
