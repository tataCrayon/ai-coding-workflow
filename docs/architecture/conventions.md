# 文档与命名约定（home repo 用）

> verified: 2026-11-23 ｜ 验证方式: 按 ADR-0003 门禁落地后实测

## 1. 文档头（强制）

每份 `docs/**/*.md` 首部：

```markdown
> verified: 2026-11-19 ｜ 验证方式: 直连 MySQL / 读源码 / 实跑命令
```

- `verified` = 上次**核对事实**的日期，不是创建/修改日期
- 只改措辞不重新核对：`verified: 2026-11-19 (wording only)`
- 只改措辞不更新日期 = 门禁失效，见 [ADR-0003](decisions/ADR-0003-doc-freshness.md)

SQL / 脚本类用 `-- verified:` 注释头。

## 2. 文件命名

| 类型 | 规则 | 例 |
|---|---|---|
| ADR | `ADR-{4位序号}-{kebab-title}.md` | `ADR-0001-home-repo.md` |
| 业务域 | `domains/{kebab-domain}/README.md` + 同目录细分文件 | `domains/permission-system/README.md` |
| Runbook | `runbooks/{动词短语}.md` / `.sql` | `runbooks/rollback-release.sql` |
| 单仓卡片 | `repos/{仓名}.md`（与目录名一致） | `repos/bff-service.md` |

**不用中文文件名**（跨平台 + git 排序 + URL 都更稳），中文放正文和标题里。

## 3. 内容纪律

| 规则 | 原因 |
|---|---|
| 只写**可验证的事实**（表结构、路径、命令、行数），不写「大概是这样」 | 本仓文档被当作全局事实源，模糊描述会被当结论用 |
| 结论带验证方式 | 下一个人能判断要不要重新验 |
| 不写 changelog / 日期化的「改造前 vs 改造后」 | 描述当前事实即可，历史在 git |
| 命令必须可复制执行 | 半截命令等于没写 |
| 不确定的标 `TODO(待验证)` | 比写成肯定句安全 |

## 4. 索引维护

- 新增/删除 `docs/` 下文档，**同一提交**内更新 `docs/INDEX.md`
- `repos/` 下的仓指针变更，更新 `repos/INDEX.md`
- 索引一行格式：`| 关键词（可多个，逗号分隔） | 路径 | 状态 |`

## 5. 与业务仓文档的分工

| 放这里 | 放业务仓 |
|---|---|
| 跨仓业务事实、权限/环境/凭证这类全局机制 | 该仓的模块结构、类图、单仓接口清单 |
| 可跨仓复用的 runbook | 单仓专属部署步骤 |
| 仓指针（位置、clone 源、边界） | 该仓的 build / test / 启动细节 |

**判据**：删掉某个仓，这份文档还有价值吗？有 → 放这里；没有 → 放那个仓。

## 6. 语言

- 正文语言跟随项目（本包默认中文），技术名词保留英文（表名、字段名、命令、错误码）
- 代码块与 SQL 一律英文注释优先，必要时中文
- 不写 emoji 装饰（`⚠️` `✅` `⛔` 仅用于风险标记，且每处必须紧跟一句具体说明）
