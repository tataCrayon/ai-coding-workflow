# ADR-0004：会话起点与仓库指针

> 状态：已采纳 ｜ 日期：2026-11-19

## 背景

home repo 只解决「可达」，不解决「深度」。如果所有任务都从本仓起，单仓排查反而更慢：
文件树、`git log`、编译报错天然在业务仓的上下文里，在本仓得额外去捞。

## 决策：按任务性质选起点

| 任务性质 | 起点 | 理由 |
|---|---|---|
| 跨仓改动（接口契约变更、跨服务联调、权限点落库） | **本仓** | 需要同时看几个仓，从单仓起会缺上下文 |
| 单仓深挖（某接口 500、某段逻辑看不懂、单仓重构） | **该业务仓** | 文件树与日志天然在上下文，搜索成本最低 |
| 不确定 | **本仓** | 先看 `repos/INDEX.md` 判范围，再决定是否进仓 |

## 指针格式（`repos/INDEX.md`）

一仓一行，必须含三要素：**定位 + 磁盘路径 + clone 源**。

```markdown
| 仓 | 定位 | 栈 | 路径 | clone |
|---|---|---|---|---|
| <bff-service> | BFF 层，聚合 + 鉴权 | JDK8 / Spring Boot 2.6 | `~/work/<line>/<bff-service>` | `ssh://git@git.example.com/<line>/<bff-service>.git` |
```

「路径不存在就 clone 到该路径」是 agent 的默认动作，不需要额外指令。
模板见 [`templates/repo-index-template.md`](../../../templates/repo-index-template.md)。

## 单仓卡片的边界

`repos/<repo>.md` **只写进仓前必须知道的事**：

- 一句话定位与不可越过的边界（如「不改某个下游仓」）
- 构建 / 测试 / 启动命令（因为这是唯一需要跨会话记忆的部分）
- 该仓独有的坑（只在这仓成立的）

**不写**：目录结构、类图、接口清单——这些进仓 `ls` / 读代码就有，写在这里只会过期。

## 与 `repos/INDEX.md` 的分工

| 文件 | 粒度 | 读者 |
|---|---|---|
| `INDEX.md` | 一仓一行表，一眼看全貌 | agent 判断「需要动哪些仓」 |
| `<repo>.md` | 单仓一页 | agent 决定进仓后、进仓前的准备 |

## 规模增长时的退化路径

超过 20 仓时 `INDEX.md` 会变长到「读它比自己搜盘更慢」，此时：

1. 按产品线拆成 `repos/<line>.md`，`INDEX.md` 只保留产品线级指针
2. 超过 100 仓时，只保留**活跃仓**（近 90 天有提交）指针，其余靠 `git` 搜索发现
