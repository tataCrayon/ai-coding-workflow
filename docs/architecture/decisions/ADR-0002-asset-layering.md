# ADR-0002：资产分层——跨仓资产进本仓，单仓资产留在原仓

> 状态：已采纳 ｜ 日期：2026-11-19 ｜ 部分被 [ADR-0005](ADR-0005-index-not-migrate.md) 取代（默认路径改为「先索引」）

## 背景

家目录下的 skill 数量常年增长（实测 80+）。做任何收编前必须先判：哪些真跨仓复用，哪些只服务一个仓。
全搬进来 = 把单仓资产升格为全局资产，每个会话都要为它付上下文成本。

## 决策：三层分类

| 层 | 判定 | 存放 | 加载方式 |
|---|---|---|---|
| **L1 通用** | 与本仓库体系无关（通用工程、AI 工程、写作、设计） | 本仓 `skills/` | 全局可用 |
| **L2 工作区** | 服务于这套工作区，跨多个仓复用（如接口文档、DB 查询、发布工单） | 本仓 `skills/` | 全局可用 |
| **L3 单仓** | 只对一个仓成立（如某仓专属发布脚本） | 该仓 `.claude/skills/` | 进该仓才可见 |

**默认判据**：一个 skill 如果**换个仓就失效**，它是 L3；如果只换**参数**还能用，它是 L2。

## 与家目录运行时目录的关系

收编进本仓后，运行时目录应保留为**镜像或链接**，原因：

- 各工具只从自己的目录（`~/.claude/skills`、`~/.agents/skills`、`~/.zcode/skills`）加载 skill，不认识本仓路径
- 直接用目录联接（`mklink /J`）把本仓目录链过去，避免「本仓改了但运行时没生效」
- 未经链接时，退化为**单向同步脚本**，本仓为源、运行时为镜像，提交前校验一致

## rules / agents 同理

| 资产 | 迁移后 |
|---|---|
| 全局 rules | L1/L2 进本仓 `rules/`，由入口文件 import |
| agents 注册表 | 进本仓，registry 作为索引 |
| hooks | 进本仓 `hooks/`，`settings.json` 指向本仓路径 |

## 迁移纪律

1. **先分类、后迁移**：出分类表，人工确认后再搬。
2. **一次只搬一层**：先 L1（风险最低），验证运行正常再搬 L2。
3. **搬之前不改内容**：内容改动和位置迁移分开提交，出问题才知道是哪一步坏的。
4. **保留回滚**：运行时侧保留归档目录，迁移失败可整体回退。

## 当前状态

默认路径已由「先分类再迁移」改为「先索引，按需迁移」，见 [ADR-0005](ADR-0005-index-not-migrate.md)。
本 ADR 的 **L1/L2/L3 分层判定依然有效**，用于「确实要搬某个资产时」判断归属。
